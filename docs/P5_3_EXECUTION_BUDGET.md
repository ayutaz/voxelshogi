## 適用と監査

1. controllerの配分変更を通常PRで取り込み、関連する必須CIと統合mainの検証を確認する。
2. 課金資源が終了した状態でledgerをロックし、旧配分26・13、過去20件の全内容、予約87・基本100を検査する。元ファイルのhashと小さい監査backupを保持する。
3. 配分だけ37・2へ更新し、既存20件・予約87・総枠100が変わらないことを検査する。controllerとledgerが一致しない状態で新規課金要求を行わない。
4. 各単位の開始直前に見積もり・workload・source・最新quote・独立期限guardを固定する。11をまとめて予約せず、実際に開始する単位だけ追加する。起動結果不明の再送はしない。
5. 各単位でHF public/manual・Community OFF・Card・固定revision全hash照合と所有資源解放を確認する。旧7局を失敗ごとにやり直したり、未完走を件数へ足したりしない。

基本枠不足が実測と最新quoteから判明した場合だけ、既存の条件付き追加100の適用を別記録へ残す。今回の変更そのものでは200への増額も実機作成も行わない。実請求が取れた時点で予約額との差を記録するが、根拠のない予約の消去・二重計上はしない。
