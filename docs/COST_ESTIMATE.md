## 3. 見積もり式

### 3.1 学習コスト（Vast.ai）

```
GPU費      = Σ_ジョブ ( コンピュート単価[$/GPU·h] × GPU数 × 実行時間[h] )
ストレージ費 = ディスク容量[GB] × $0.20/GB·月 × 保持期間[月]
転送費      = 転送量[TB] × 転送単価[$/TB]
基礎額 B    = GPU費 + ストレージ費 + 転送費

総額[USD]   = B × (1 + 失敗・再実行率 r) × (1 + 予備費率 c) × (1 + 為替手数料 f)
総額[JPY]   = 総額[USD] × USD/JPY
```

実出品でディスク込みの `dph_total` を使う場合は、`Σ(設定済みインスタンス単価 × 実行時間)` を使い、その期間のディスク費を重ねて加算しない。停止後の保持費・転送費など、表示総額に含まれない費用だけを別途足す。インスタンス全体の単価にはGPU数を再度掛けない。

| パラメータ | 既定値 | 区分 | 根拠 |
|---|---|---|---|
| 失敗・再実行率 r | **+20%**（インタラプティブル主体なら +30〜35%） | [仮定] | ホスト障害、OOM、設定ミス、起動直後の環境構築・データ DL 時間 |
| 予備費率 c | **+15%** | [仮定] | 価格変動、追加実験 |
| 為替手数料 f | **+3%** | [仮定] | カード為替 |
| USD/JPY | **¥157**（ストレス ¥165） | [市場] | §1 |
| 合成倍率 (1.20×1.15×1.03) | **1.4214** | 計算 | |

### 3.2 必要 GPU 時間の式（実測後に使う）

```
自己対局 GPU·h = (対局数 G × 平均手数 L) / (自己対局 手/秒/GPU × 3600)
学習 GPU·h     = (学習サンプル数 P × エポック相当 E) / (学習 局面/秒/GPU × DDP効率 η(n) × 3600)
オーバーヘッド h = 起動回数 × (イメージ取得+環境構築+データ DL)[分] / 60   ※GPU 数分課金される
評価 GPU·h      = 評価対局数 × 平均手数 / (評価 手/秒/GPU × 3600)
```

- **現時点で上式の分母（手/秒、局面/秒、η）はすべて未実測**。§6 の計測を行うまでは「予算 → 使える GPU 時間」の逆算（§3.3）で管理する。

## 5. Cloudflare・ドメインの運用コスト

### 5.1 Workers / Static Assets [公式]

| 項目 | Free プラン | 区分 |
|---|---|---|
| 静的アセットへのリクエスト | **無料・無制限**（Free/Paid とも） | 現行料金では従量課金なし |
| 静的アセットの保存 | 追加料金なし | 現行料金では追加料金なし |
| Worker スクリプト呼び出し | **100,000 リクエスト/日**（UTC 0 時リセット、超過は Error 1027 または fail-open） | 無料枠内 |
| CPU 時間 | 10 ms / 呼び出し | 無料枠内 |
| Paid（Standard） | $5/月〜、1,000万リクエスト/月・3,000万CPU ms/月込み。超過は$0.30/100万リクエスト・$0.02/100万CPU ms | 有料 |

- 本プロジェクトは **Worker スクリプトなしの静的 SPA** にすれば、配信は実質 $0。
- **費用が発生し得る落とし穴**: (1) `run_worker_first` で Worker を経由させると日次 100k の対象になり、超過時は 429。(2) **Workers Caching を有効化すると、キャッシュから返した静的アセットのリクエストも課金対象**になる。現在の静的SPAではどちらも未使用。ここでいう追加機能のWorkers Cachingは、Static Assetsの通常のCDNキャッシュや `/assets/*` のimmutable設定とは別物。[Static Assets](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/)、[Workers料金](https://developers.cloudflare.com/workers/platform/pricing/)、[Workers Caching](https://developers.cloudflare.com/workers/cache/)

計算は「起動・ビルド＋試行＋本生成＋全件検証＋全再生成・照合＋退避」の所要時間に、選んだ構成全体の時間単価を掛け、別課金の保存・転送と失敗時の余裕を加える。料金内に含まれる資源を二重加算しない。外部試行で得た速度に置き換えて残予算を再判定し、上限超過の見込みなら本生成前に停止・再見積もりする。

今回は少量の初回試行だけを承認対象とし、本生成は実測後に別の時間・総額を提示する。M4のCPU費用・データ公開・M6のGPU費用はそれぞれ別に判断する。現段階では契約・入金・課金や10万局面のMac生成を始めない。
