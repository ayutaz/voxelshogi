# P5-3d：着手方法だけを変える診断

## 目的と完了条件

150局比較で観測した失敗から、同じ重みの使い方を1要因だけ変えて調べる。固定対照と変更条件の全対局をRustで再生し、入力監査・HF固定revisionの全hash・資源解放を確認した後に、採用・棄却・追加測定を記録する。追加学習、Phase6、新モデルのWeb採用は今回行わない。

## 選択の根拠

2026-11-04の比較sourceは`49b3f31d69039831c8770239d875f09a1f75879f`。150局の対局部分は完走し、M6・子3世代・M1対照が各30局そろった。[全入力監査・HF保存・実機解放](P5_3_COMPARISON.md)まで完了した。ただしM6の1対局で保護集合との重複4件を検出したため、漏洩のない棋力評価とは扱わない。該当対局も含む全150局を保持する。

同系統の1手詰め3局面の先手では、M6が2勝・1 cutoff、第1世代が3勝、第2世代が2勝・1 cutoff、第3世代が1勝・2 cutoffだった。後手側は全モデルで3敗であり、同じ局面の色交換である。3件を独立した戦術familyとは呼ばない。全30局の勝数はM6／第1／第2／第3世代が2／3／2／1、cutoffは12／8／9／9。これだけで世代の棋力向上・低下を確定しない。

そこで第3世代の重みを固定し、合法Policy argmaxから、既存のPolicy／Valueを使うノイズなしPUCTへ着手方法だけを変える。自己対局の学習時に使った探索と、今回のargmax評価の違いを切り分けるための診断であり、PUCTの効果を先に仮定しない。

## 固定する条件と数量

| 条件 | 内容 |
|---|---|
| モデル | 第3世代FP32、SHA-256 `bf4fba2699d9d8578a821766b0fcaf861d56aab3effc296d87ec3a4e9408c8a4` |
| 局面 | 本比較の`mate-offset-2`・`mate-offset-3`・`mate-offset-4`の全3件。診断結果を見て取捨選択しない |
| 対照 | `legal-argmax-v1`、同率なら最小のcanonical action ID |
| 変更 | `puct32-v1`：32 simulations、depth64、cpuct1.0、root noiseなし、温度samplingなし、毎手新しいtree、最大訪問数・同率なら最小ID |
| 共通相手 | Rust M1、深さ3・20,000ノード・TT4,096 |
| 共通上限 | 元の開始履歴・seed・先後交換・追加1手を保持。cutoffを敗北・引分へ読み替えない |
| 件数 | 3局面×先後2×対照／変更2＝12局。150局や時間試行8局へ合算しない |
| 実行 | 同じclean source・Linux runtime・GPU・FP32条件で両条件を新規実行。元150局の条件や結果を変更しない |

実行前に両protocol・全重みhash・取得revision・runtime・停止期限・費用上限を固定する。入出力・TF32・乱数設定も両条件でそろえる。既存のPolicy／Value loaderは合法手だけの確率と手番側Valueを返し、公開重みのhash・FP32・有限値を照合する。PUCTの設定はpolicy名とsourceで固定し、隠れた予算変更やORTへの代替実行を許可しない。

既存の評価v2 runner、局面ごとの並列runner、中断poolのarchiveにも新policyの重み役割を伝える。停止はPUCT内部まで伝播し、32回未完了・停止済みの探索や不正な手を完了対局へ変換しない。ゲームのルールはRustだけが担当する。

## 検証と判断

Macではmetadataと小さい手計算treeだけを確認する。ネットのpriorが負ける手を優先しても、終端Valueから勝つ手を選ぶこと、32／64／1.0の固定条件、停止・部分探索・違法手の拒否、実際のweight／stop portの伝達を検証する。最初の新規テストは9件失敗・3件成功から実装した。探索内の観測と追加入力監査も9件失敗から接続した。

Linux CIでは、手書きの詰み手`232222`を期待値にする実Rust＋CPU Torchのloader／PUCT／先後交換と、片色確定後の中断再開・元byte保持・集約を検証する。CIの小さい重みfixtureを実モデルの棋力やGPU速度の証拠にはしない。関連CI・全必須チェックが成功するまで実機診断を開始しない。

逐次runnerの`observe_input(role, game)`は、argmaxが参照した局面とPUCTが実際にモデル照会した全非終端局面を観測する。PUCTの枝の入力を実際の着手経路だけで代用しない。手番正規化入力／物理局面の集合を記録し、`audit_generation_runs(..., observed_inputs=...)`で全着手経路・終端と一緒に照合する。観測値だけから合法性を主張せず、局面はRust snapshotから作る。

実機では両条件の全12局を再生・再集計し、M4全split、全P5-2公開sample、保護集合との物理局面／手番正規化入力の重複を全件調べる。全結果と実時間、各条件の自然勝敗／cutoff、手計算の詰み手との一致、監査と限界を公開する。保存先は`voxelshogi/`のpublic/manual・Community OFF、CC-BY-4.0のDataset Card付きとし、外部Linuxから公開ハーネスで送信・固定revision全hash照合を行う。

3件が同familyであることから、改善しても一般的な棋力向上やWeb採用は主張しない。失敗しても条件・探索回数を後付けで変えず、棄却または追加測定として記録する。実機診断の見積もりと借用は150局の保存・解放後に確定し、承認済み総枠200と共通ledgerを守る。この診断の後も、今回の「5まで」に含む実1／2／4GPU・各保存再開は引き続き必要である。
