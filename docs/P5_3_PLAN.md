## 実装の接続先

- [固定した局面定義とLinux生成](../training/generation_cases.py)：時間試行2局面と本比較15局面を分離し、戦術3件が同じfamilyの変形であることも明示する。Rustで全開始履歴・手計算の詰みoracle・入力IDの一意性を確認する。
- [世代差の集計と入力集合の監査](../training/generation_evaluation.py)：共通条件・同じ先後pairを検査し、M6との差を10,000回再標本化する。cutoffの勝点範囲を保持する。
- [全コーパス・後続入力の監査](../training/generation_audit.py)：M4全split、全P5-2公開sample、保護入力を列挙し、評価開始後の全局面・終端を物理局面と手番正規化入力の両方で照合する。固定revision取得とhash照合は実行側の先行条件である。
- [評価runner](../training/evaluation_v2_runner.py)の`--resume`：各対局をhash付きreceiptへ確定し、再開時に同じprotocol・全保存hash・metadata・Rust再生を検査して完了済みを再利用する。未確定ファイル・同時実行・条件や環境の変更は拒否する。既定の新規実行は既存出力を上書きしない。
- [局面ごとの並列評価](../training/evaluation_jobs.py)：全cohortのprotocolを縮めず、1開始局面・先後2局を1仕事にする。5 cohort×15局面＝75仕事・150局。同時実行は1〜16プロセスに制限し、各色の確定hashを再開時にも保持する。集約はRustで再生した元ファイルのbyteをそのままコピーし、全局面・先後・runtimeの一致を要求する。起動結果が不明な仕事や生存中のPIDを自動で再起動しない。

並列評価のLinuxコマンドは `uv run --project infrastructure/cuda --locked python -m training.evaluation_jobs pool --plan PLAN.json --artifacts ARTIFACTS.json --output OUTPUT`。planは `plan_case_jobs` から作り、artifactsはcohortごとのroleと固定重みのpathを持つ。再開だけ `--resume` を明示する。完了済み対局は再実行せず、停止signalは所有する子へ伝える。入力監査・HF公開・費用と絶対期限の制御は外側の実行単位で引き続き必要であり、並列runner単独の成功を実験全体の完了としない。

2026-11-04の最初の試行は7／8局で時間上限となり、保存済み7局をHFへ退避した。残り1局と全入力監査は未完了。[試行記録](P5_3_TRIAL.md)を保持し、ここから並列化の実効果と本比較の時間を実GPUで測る。CIの速度やGPU使用率の小ささから、対局の並列化率を測定済みとしない。

小さいmetadata／fake portsの45テストと新規12変異はMacの軽量確認で検証した。実局面・全手再生・実中断再開はLinux CIのNativeテストで検証し、実GPU・8／150局・1／2／4GPUの完了とは分ける。

P5-4の[共通データ順](../training/distributed_benchmark.py)も準備する。同じglobal batchと更新数から全更新のsample indexを固定し、1／2／4 rankへ重複もpaddingもなく等分する。Valueの出所が異なるsampleは同じbatchに混ぜず、端数はGPU数によらず全体で除外して件数を記録する。純粋な13テストと3変異で確認した範囲は、このスケジュールだけである。DDPの勾配同期・保存再開・実GPU時間／VRAM／通信／費用の完了を意味しない。

### 局面と監査

- 15開始局面の内訳案は短い戦術3、少数駒4、長い履歴4、標準序盤4。分類・履歴・追加手数・seedを対局前に固定する。履歴が長いだけで代表的な中終盤と呼ばない。
- 同一familyの変形は明示する。15組のopening-pairを独立した15戦術と呼ばず、同じ開始局面を全モデル・先後で共有する。8局の時間試行は別集合とする。
- M4／M6とP5-2の全世代の実学習入力、および保護集合と照合する。評価開始局面だけでなく、開始後の全継続局面・終端を対象に、物理局面と手番正規化されたモデル入力IDの両方を調べる。共通prefixの扱いと履歴も記録する。
- 現行`evaluation_cases.audit`の凍結M6コーパス・物理局面監査だけでは、この後続データ・正規化入力の要件を満たさない。共通入力IDとP5-2の監査を再利用して接続し、非空の対象件数・重複・除外・hashを確認する。重複を見つけた結果を非重複評価と呼ばず、都合の良い対局だけ削除しない。
- 実行ごとのsourceとparticipantを結ぶ機械可読protocolは、固定した局面定義から外部Linuxで作成する。元の8局面generatorと過去の評価は保持し、今回の15局面・全世代との漏洩監査・差分集計を専用経路へ分ける。実対局前にprotocol・hash・取得receiptを保存し、試行の結果で本比較の局面を選び直さない。

### 集計と終了の基準

勝ち・負け・自然引分・cutoffを分け、各モデル30局・対照30局、全体150局の件数を照合する。全対局をRustで再生し、保存後もhash・宣言結果・集計を再検査する。途中停止・欠落・失敗を完走に含めない。再実行は保存した実行状態を調べてから行い、完了した対局を上書きしない。

先後2局を単位に10,000回のpaired bootstrapを行う。M6との差も同じopening-pairをそろえた差分で集計する。既存の単一比較の集計だけで世代間の差の区間を計算済みとはしない。cutoffを各0〜1点とした全局の勝点範囲と、その差の上下限も併記する。関連family・小標本の限界を残し、全cutoffや0勝の狭い区間を強さの保証にしない。

本比較は`purpose=development`。感度screen案は各比較15組以上・自然終局率25%以上で、試行・本比較前に固定する。自然引分が多い場合はscreenを通っても勝敗差を捉えられるとは限らない。低感度、重複、悪化、差不明も結果として公開し、条件変更は新protocolに分ける。150局が完走して結果と限界を報告できれば初回の世代比較を完了とする。一般的な棋力向上や正式採用の判断には別に必要な証拠をそろえる。
