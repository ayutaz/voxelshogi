# M4 実行計画：GPUサービス上でのPython連携とデータ生成

策定・更新: 2026-10-28 JST。**M4-0〜2を実装・統合済み。M4-3は外部実機での計測前。** 契約は [M4_DATA_CONTRACT](M4_DATA_CONTRACT.md)、完了済みの検証は [M4_VALIDATION](M4_VALIDATION.md)。ユーザー指定でMac計測を行わず、Vast.ai／CloudRiftのGPUサーバーのCPUで生成を計測し、後のGPU学習も同じサービスで行う。[初回試行の見積もりと準備](M4_REMOTE_PLAN.md)。本生成・外部契約・課金・データ公開は未実施。[ROADMAP](ROADMAP.md#m4-python-バインディングとデータ生成phase-3-の本体)の完了条件を具体化する。

## 目的とゴール

観戦用モデルの学習・比較に使えるデータを、普段使うMacを長時間占有せずに作る。RustのルールをPythonから共有し、生成・検証・再現・中断再開を先に確立してから規模を広げる。

| ゴール | 完了を確認するもの |
|---|---|
| Pythonから同じルールと探索を使える | PyO3境界、行動マスク付き環境、独立期待値・Rustとの照合、Python3.14とCI。依存が未対応の場合だけ理由を記録して3.13へ切り替える |
| 初回外部試行を制限できる | 1ワーカー、実行時間・プロセス群メモリの監視、停止・再開・未完了データの除外テスト。Macでは実行しない |
| 本生成の時間と費用を判断できる | 小規模試行の実測、外部CPU候補の現行見積もり、承認した利用時間・総額・停止条件 |
| 約10万局面を検証できる | Parquet、全件の履歴再生・合法手・教師の整合、不正・重複の検出、対局単位の分割 |
| 再生成と再開でデータが変わらない | 固定環境で全データを再生成したhash、途中停止からの再開と連続実行の一致 |
| 配布準備が整う | Dataset Card、公開dry-run、生成設定・hash・実測記録、通常PRと必須CI。実公開はライセンス・公開方法の確定後 |

## 実行環境の役割

従来のMacでの少量確認はM4-0〜2の固定した履歴として保持する。以後の方針は以下を優先する。大規模実行経路はまだ用意していない。内部APIの小規模テストと、外部pilotの計測結果を区別する。

| 作業 | 実行場所と上限 |
|---|---|
| 編集・軽量な確認 | Macでは編集、文書・構文・小さい純粋関数の確認のみ。探索・生成・計測・学習や重い回帰検証を走らせない |
| 生成器の動作確認・計測 | 承認後のVast.ai／CloudRift。初回は1ワーカー・内部スレッド1、1回最大5分・試行合計10分。pilot既定は240秒。Macへのfallbackはしない |
| 初回試行の資源監視 | 所有子プロセス群RSS合計1 GiBと、利用可能メモリ・swapを監視。監視不能時も停止。ホストのRAM・cgroup割当と観測範囲も記録する |
| 本生成・全件検証・全再生成 | 同じGPUサービスのCPUを使う。実測から対象構成・並列数・ストレージ・時間・総額を見積もり、別途承認後に使う |
| CI | 固定した少量のfixtureで境界・生成・検証・停止再開・再現性を確認。約10万局面を毎PRで作らない |

親プロセス側の経過時間監視で、Rust探索がPythonへ戻らない間も所有する子プロセス群を停止する。RSSは監視による停止基準であり、瞬間的な超過まで防ぐハード上限とは区別する。利用可能メモリとswapも監視する。[閾値と対象範囲](M4_DATA_CONTRACT.md#実行と制限)。以後はMacで生成・性能計測を実行せず、重いビルド・回帰検証もCIまたは承認済み外部環境で行う。

制限のテストは注入した時計・メモリ観測値と制御した子プロセスを使い、境界超過、ネイティブ処理中の停止、子の残存なし、未完了データの除外、再開結果を確認する。テストのために実際に5分待ったり、大量のメモリを消費したりする必要がない形にする。

## データと再現性の契約

- 対象は標準1王。9王の正式採用は別の判断とし、異なるrulesetのデータを混ぜない。[MODEL_CONTRACT](MODEL_CONTRACT.md)の43ch入力・Policy 1,067,985・scalar Valueと接続する。
- 局面だけでなく再生に必要な履歴、対局ID・手数、適用手、合法行動ID、生成元、探索評価・推奨手・完了深さ・ノード数・停止理由を保持する。探索評価の視点と尺度を記録し、駒得評価を勝率へ無根拠に変換しない。
- 教師は固定深さ／ノード上限を使う。深さ1以上を完了していない代替手は最善手ラベルから除く。壁時計上限で停止した未完了部分は不採用とし、同じ設定で後から再実行する。停止のために探索条件を途中で弱めない。
- 大きなPolicyの密なマスクや学習用テンソルを全件RAMへ積まない。合法行動IDとコンパクトな局面を分割保存し、マスク・特徴量は必要な単位で展開する。分割サイズは実測から決める。
- 対局IDとseedから乱数系列・保存順・分割先を決め、ワーカー数や処理完了順で結果を変えない。未完了ファイルはmanifestへ登録せず、完了した分割だけを原子的に確定する。
- 再生と教師設定の整合を全件検証する。重複の判定キー・許容する反復を固定し、同一対局の分割混在を禁止する。対局をまたぐ同一局面の評価側への漏れも検出し、除外方針と除外数を記録する。
- 所要時間・RSS・実行日時等の可変な観測値はデータ本体から分けて保存する。固定した生成環境・依存lock・保存順・Parquet設定で、データファイルと決定的なmanifestのSHA-256を再生成照合する。既存のMac記録は論理内容を照合する際の固定資料として使い、Macで再生成しない。異なる環境間のバイト一致を未検証のまま保証しない。
- 全再生成は本生成と同じ固定環境で行う。そのCPU時間・2組分の保存領域も見積もりに含める。CIの少量一致だけを、約10万局面の全再生成の証拠にしない。

## 外部CPUの選定と費用の判断

利用可能なサービスはVast.ai／CloudRiftのみ。認証付き一覧で4090×1は空き0だったため、初回はCloudRift米国のRTX 5090×1（14論理CPU・Dedicated、RAM48 GiB）を第一候補にする。[取得時の料金・代替候補・利用承認前の提案](M4_REMOTE_PLAN.md)。Rustのαβ探索はCPU実装であり、GPU込みの料金を支払ってCPU処理する期間も見積もる。GPUを追加するだけで探索が速くなる前提は置かない。

見積もりには、対象データの件数・教師の深さ／ノード、測定環境・コミット、局面/秒、検証・再生成の時間、構成と現在の単価・取得日、起動／ビルド、保存／転送、失敗時の余裕、最大利用時間・総額・停止／退避手順を含める。[費用見積もり](COST_ESTIMATE.md#m4の外部cpu生成見積もり2026-10-28追加計画)に反映し、具体的な見積もりを承認後に契約・課金を始める。

Macの速度から外部のコア数倍の高速化を仮定しない。今回は少量の外部試行だけを範囲・時間・金額付きで提示し、本生成は実測後に別途見積もり承認を得る。外部の実測で予算内に収まらなければ停止して再見積もりし、同じ予算内でもデータ件数や教師の品質を無断で下げない。ジョブの時間上限だけで課金終了を保証せず、計算資源の終了と残るディスク等を確認する。

生成物は公開前の作業データとして扱い、PRや公開artifactへ自動添付しない。認証情報は環境変数で扱う。承認済みのM3モデルのライセンスを、M4データセットへ流用しない。

## M5以降との関係

M5は実棋譜がそろい次第挿入し、重い検証は同じ外部運用へ寄せる。M6もMac MPSでは始めず、同じGPUサービス上でCUDA依存・小規模学習を確認する。学習の時間・総額は別途承認後に使い、初回pilot承認を本生成・本学習・データ公開へ拡大しない。Phase 5〜7の規模・予算はM6の実測後に確定する。
