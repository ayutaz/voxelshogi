# M4 実行計画：Macの負荷を抑えたPython連携とデータ生成

策定・更新: 2026-10-28 JST。**M4-0〜2のPython連携・少量生成・検証・停止再開を実装。** 契約と実行方法は [M4_DATA_CONTRACT](M4_DATA_CONTRACT.md)、テストと取り込みの確認元は [M4_VALIDATION](M4_VALIDATION.md) に記録する。M4全体は未完了で、次はM4-3の計測と外部CPU見積もり。本生成・外部契約・データ公開は未実施。[ROADMAP](ROADMAP.md#m4-python-バインディングとデータ生成phase-3-の本体)の完了条件を具体化する。Macは開発と短い動作確認に使い、約10万局面の本生成・全件検証・再生成は外部CPU環境を第一候補とする。

## 目的とゴール

観戦用モデルの学習・比較に使えるデータを、普段使うMacを長時間占有せずに作る。RustのルールをPythonから共有し、生成・検証・再現・中断再開を先に確立してから規模を広げる。

| ゴール | 完了を確認するもの |
|---|---|
| Pythonから同じルールと探索を使える | PyO3境界、行動マスク付き環境、独立期待値・Rustとの照合、Python3.14とCI。依存が未対応の場合だけ理由を記録して3.13へ切り替える |
| Macの試行を制限できる | 1ワーカー、実行時間・プロセス群メモリの監視、停止・再開・未完了データの除外テスト |
| 本生成の時間と費用を判断できる | 小規模試行の実測、外部CPU候補の現行見積もり、承認した利用時間・総額・停止条件 |
| 約10万局面を検証できる | Parquet、全件の履歴再生・合法手・教師の整合、不正・重複の検出、対局単位の分割 |
| 再生成と再開でデータが変わらない | 固定環境で全データを再生成したhash、途中停止からの再開と連続実行の一致 |
| 配布準備が整う | Dataset Card、公開dry-run、生成設定・hash・実測記録、通常PRと必須CI。実公開はライセンス・公開方法の確定後 |

## Macと外部環境の役割

生成・検証CLIに以下の制限を実装した。M4-3以降の大規模実行経路はまだ用意していない。内部APIを直接呼ぶテストと、負荷上限付きのCLIを区別する。

| 作業 | 実行場所と上限 |
|---|---|
| Python境界・生成器の開発 | Mac。Rustビルドは1ジョブ、Pythonテストは関連する小規模集合から実行。フルの回帰・変異検証はPRのCIでも行う |
| 生成器の動作確認・計測 | Mac。生成・検証を含むプロセス群は1ワーカー、ネイティブライブラリの内部スレッドも1にする。1回は最大5分、1作業セッションの試行合計は最大10分。自動でバッチを連続起動して上限を迂回しない |
| Macでのメモリ・操作感 | 生成・検証プロセス群のRSS合計1 GiBを初期停止基準とする。OSのメモリプレッシャー上昇、swapの継続増加、操作の支障があれば時間内でも停止。RSSは共有ページを重複計上し得るため、計測方法とOSの状態を併記する |
| 本生成・全件検証・全再生成 | 外部CPU環境。対象構成・並列数・ストレージ・実行時間・総額を見積もって承認後に使う。Macへの全件生成への自動切替はしない |
| CI | 固定した少量のfixtureで境界・生成・検証・停止再開・再現性を確認。約10万局面を毎PRで作らない |

低優先度実行だけではCPU使用率や発熱の上限は保証できない。親プロセス側の経過時間監視で、Rust探索がPythonへ戻らない間も所有する子プロセス群を停止する。RSSは監視による停止基準であり、瞬間的な超過まで防ぐハード上限とは区別する。OS負荷の自動判定には利用可能メモリとswap増加を使い、macOSのGUIのメモリプレッシャーとは区別する。[閾値と対象範囲](M4_DATA_CONTRACT.md#実行と制限)。日常利用への影響が残る場合は、Macの生成試行を縮小・中止し、外部での確認へ移す。ビルドも重い処理を同時起動しない。

制限のテストは注入した時計・メモリ観測値と制御した子プロセスを使い、境界超過、ネイティブ処理中の停止、子の残存なし、未完了データの除外、再開結果を確認する。テストのために実際に5分待ったり、大量のメモリを消費したりする必要がない形にする。

## 実装順とPRの分割

各実装段階でTDDのRED/GREEN、独立期待値、対象の変異検出を行い、作業ブランチ・必須CI・通常mergeを使う。以下は順序と成果物であり、各段階の所要時間はまだ未確定。

| 順 | 目的と作業 | ゴール・次へ進む条件 |
|---|---|---|
| M4-0 | データと資源制限の契約を固定 | Python3.14でPyO3／maturin・Parquet等の依存互換性と空き容量を確認。schema、標準1王のruleset、seed、教師設定、上限、観測項目を確定。新依存はuvで管理 |
| M4-1 | RustエンジンをPythonへ接続 | 局面・履歴・合法手・適用・終局・探索を公開。行動IDと特徴量を既存M3契約へ照合し、ルールをPythonへ再実装しない。行動マスク付き環境を検証 |
| M4-2 | 少量の生成と検証を実装 | ランダム・ルール由来・探索教師を区別して保存。Parquetと独立検証器、対局単位の分割、停止監視、チェックポイントと再開を少量のデータで確認 |
| M4-3 | Macの短い試行から見積もりを作る | 序盤・中盤・終盤の固定集合で局面/秒、完了深さ、停止理由、RSS、出力サイズを記録。5分／合計10分以内。未完了の試行も記録し、外部CPU候補の見積もりを提示 |
| M4-4 | 承認範囲で外部CPUの試行をする | 対象環境の少量データでMacとの論理内容の一致、速度、並列効率、メモリを確認。利用料込みの残予算で本生成・検証・再生成まで収まるか再判定。超える場合は本生成前に見積もりを更新して承認を得る |
| M4-5 | 約10万局面を生成・全件検証する | 分割生成、全件照合、重複と分割漏れの確認、固定環境での全再生成hash一致を記録。データを退避しhashを照合後、承認範囲の計算資源を終了し、保持ストレージ等の継続費用も確認 |

## データと再現性の契約

- 対象は標準1王。9王の正式採用は別の判断とし、異なるrulesetのデータを混ぜない。[MODEL_CONTRACT](MODEL_CONTRACT.md)の43ch入力・Policy 1,067,985・scalar Valueと接続する。
- 局面だけでなく再生に必要な履歴、対局ID・手数、適用手、合法行動ID、生成元、探索評価・推奨手・完了深さ・ノード数・停止理由を保持する。探索評価の視点と尺度を記録し、駒得評価を勝率へ無根拠に変換しない。
- 教師は固定深さ／ノード上限を使う。深さ1以上を完了していない代替手は最善手ラベルから除く。壁時計上限で停止した未完了部分は不採用とし、同じ設定で後から再実行する。停止のために探索条件を途中で弱めない。
- 大きなPolicyの密なマスクや学習用テンソルを全件RAMへ積まない。合法行動IDとコンパクトな局面を分割保存し、マスク・特徴量は必要な単位で展開する。分割サイズは実測から決める。
- 対局IDとseedから乱数系列・保存順・分割先を決め、ワーカー数や処理完了順で結果を変えない。未完了ファイルはmanifestへ登録せず、完了した分割だけを原子的に確定する。
- 再生と教師設定の整合を全件検証する。重複の判定キー・許容する反復を固定し、同一対局の分割混在を禁止する。対局をまたぐ同一局面の評価側への漏れも検出し、除外方針と除外数を記録する。
- 所要時間・RSS・実行日時等の可変な観測値はデータ本体から分けて保存する。固定した生成環境・依存lock・保存順・Parquet設定で、データファイルと決定的なmanifestのSHA-256を再生成照合する。Macと外部Linuxの比較はまず論理内容で行い、異なる環境間のバイト一致を未検証のまま保証しない。
- 全再生成は本生成と同じ固定環境で行う。そのCPU時間・2組分の保存領域も見積もりに含める。CIの少量一致だけを、約10万局面の全再生成の証拠にしない。

## 外部CPUの選定と費用の判断

現時点では事業者・構成・金額を確定しない。専用CPU／vCPUの違い、実効速度、RAM、ディスク、転送、終了後の課金を調べ、CPU用インスタンスを優先して比較する。Rustのαβ探索は現在CPU実装であり、GPUを追加するだけで速くなる前提を置かない。

見積もりには、対象データの件数・教師の深さ／ノード、測定環境・コミット、局面/秒、検証・再生成の時間、構成と現在の単価・取得日、起動／ビルド、保存／転送、失敗時の余裕、最大利用時間・総額・停止／退避手順を含める。[費用見積もり](COST_ESTIMATE.md#m4の外部cpu生成見積もり2026-10-28追加計画)に反映し、具体的な見積もりを承認後に契約・課金を始める。

Macの速度から外部のコア数倍の高速化を仮定しない。最初の承認は少量の外部試行と、条件を満たす場合の本生成までを範囲・時間・金額付きで提示する。外部の実測で予算内に収まらなければ停止して再見積もりし、同じ予算内でもデータ件数や教師の品質を無断で下げない。ジョブの時間上限だけで課金終了を保証せず、計算資源の終了と残るディスク等を確認する。

生成物は公開前の作業データとして扱い、PRや公開artifactへ自動添付しない。認証情報は環境変数で扱う。承認済みのM3モデルのライセンスを、M4データセットへ流用しない。

## M5以降との関係

M5は実棋譜がそろい次第、短い互換性検証として挿入する。大きい検証集合は同じ外部CPU運用へ寄せる。M6ではMac MPSの短い学習確認から始め、有料GPUは別の見積もりと承認後に利用する。M4の外部CPU承認をGPU利用やデータ公開の承認と扱わない。Phase 5〜7の規模・予算はM6の実測後に確定する。
