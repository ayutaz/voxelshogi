# VoxelShogi プロジェクト仕様

## 目的

9×9×9 の三次元将棋（729マス・372枚）を題材に、**再現可能な三次元将棋 AI 研究プラットフォーム**を OSS として提供する。次の要素を一貫して開発・公開する。

**主用途はAI同士の対局を見て・眺める観戦であり、その体験を支えるモデルの開発と研究を行う。** ゲームとして面白く、初見でも状況が分かり、見映えのよい体験を目指す。人間対AIは補助的な参加方法とし、人間同士の対局・マルチプレイは想定しない（2026-10-26 ユーザー指定）。

1. Rust ルールエンジン（Rust ネイティブ、WASM、Python から同じロジックを使う）
2. 誰でも無料でAI対局を観戦できるブラウザゲーム「VoxelShogi Arena」（Cloudflare）
3. エンジンで生成した合成データセット（Rules / Search / Self-play / Tactical）
4. Transformer ベースの Policy/Value モデル（S: 5–10M、M: 20–35M パラメータ）
5. Vast.ai／CloudRiftでの1〜4 GPU学習環境（DDP、再開可能なチェックポイント）
6. AI vs AIをブラウザ内推論で実行し、人間 vs AIも補助機能として提供する（GPU サーバーは常時稼働させない）
7. GitHubとHugging Faceの`voxelshogi/`配下への公開（public・ダウンロード申請は手動承認）

**新規性について**: 「初めての三次元将棋」ではない。新規性は次の2点にある。

- エンジン・データ・モデル・自己対局・分散学習を、一貫して公開すること。
- 729 トークンの三次元空間に対して、3D-CNN、Full Attention、Axial Attention、Geometry-Aware Attention を、同じ計算予算で比較する研究。

詳細は [RELATED_WORK.md](RELATED_WORK.md) を参照。これは目指す研究上の貢献であり、学習・アーキテクチャ比較を実施済みという意味ではない。

## スコープ

| 含む | 含まない（初期） |
|---|---|
| AI vs AI観戦を主とし、人間 vs AI、棋譜の保存・再生・共有も提供 | 人間同士の対局（ローカル・オンライン）、マルチプレイ |
| ブラウザ内推論（WebGPU、利用者が明示選択するWASM） | サーバー側での常時 GPU 推論 |
| 同一ホストでのマルチ GPU（DDP） | 複数ホストにまたがる分散学習 |
| 独自エンジンで生成した合成データ。第三者の公開棋譜はM5の少量・非公開の互換性確認のみ | 第三者棋譜の学習用収集・再配布 |

対局モードは人間 vs AI と AI vs AI 観戦に限定する。人間同士の対局・マルチプレイは、後続フェーズにも追加しない（2026-10-25 ユーザー指定）。

## 観戦体験と研究の優先順位

1. **分かりやすさ**: 対局開始時に勝利条件を示し、どちらのAIが何を指し、優劣・勝利までの進捗がどう変わったかを追えるようにする。複数王を採用する場合は、対象の王と捕獲数を見失わない表示を検証する。
2. **眺める面白さと見映え**: 着手・捕獲・王への攻撃・決着の見せ方、注目層の切り替えなどを試作し、盤面の可読性と合わせて選ぶ。放置して観戦でき、一時停止・1手送り・速度変更で追い直せるようにする。
3. **モデルを比較できること**: 両AIのモデルID・精度形式・推論backend・探索条件を識別し、棋譜と再現条件を残す。評価値の視点・尺度を明示し、実測した勝率とは区別する。
4. **対局の質と表示の評価**: 終局率・対局長・先後の偏り・展開と、観戦の理解しやすさ・描画・推論性能をそれぞれ記録する。再生速度やカメラの違いでルール自体の良し悪しを断定しない。対象実機では3D表示と推論を同時に動かして確認する。

人間同士のプレイテストは完了条件に含めない。AI同士の比較対局、観戦画面の実機操作、必要に応じた人間対AIで検証する。

## 横断的な要件

- すべての棋譜とデータに `ruleset_id` を付ける。標準は `voxelshogi-standard-v1`、9王試作は `voxelshogi-nine-kings-{first5,all,score}-v0` の3種。初期配置・終局条件が異なる棋譜・教師ラベルを混ぜない。[ルール仕様](RULESET.md)
- 再現性: 乱数シード、エンジンの Git コミット、生成アルゴリズムのバージョンを保存する。対局単位で train/val/test に分割する。
- 教師ラベルには、出所を区別するメタデータを付ける（ルールによる確定値、探索による推定値、自己対局の統計値）。ランダム AI の手や、深さ1以上の完了反復がない探索の代替手を「最善手」として保存しない。探索教師の再生成には固定深さ／ノードを使い、時間だけの上限を同一出力の保証条件にしない。
- Web デモ: 対象の実機のブラウザで、配信用に変換したモデルそのものを動かし、人間 vs AI・AI 観戦で試せるようにする。Web 向けに作成・評価した実行可能な変換版は、採用版・比較版を問わずすべてデモで選択できるようにする。量子化・FP16化などで精度が下がった版も対象とする。モデル名・精度形式・実際の推論 backend を表示し、未対応の実機では理由を示す。
- モデル評価と配信の一致: 変換前の基準モデルと、各変換済みモデルの精度・棋力・速度・サイズを比較する。評価した配布ファイルとデモで読み込むファイルの SHA-256 を一致させ、Model Card から追跡できるようにする（外部データ形式の重みを使う場合は全ファイルを対象にする）。量子化による差と runtime 間の実装誤差は別に検証する。
- 実行・保存場所: Macは編集・読み取り・軽量確認のみ。探索・生成・計測・学習は承認済みVast.ai／CloudRift、重い回帰検証はLinux CIへ置く。データと学習checkpointはMacへ中継せず、外部LinuxからHFの`voxelshogi/`配下へ直接転送・固定revisionで照合する。M4合成データv1のCC-BY-4.0はユーザー承認済み。学習済みモデルのライセンスは別途確定する。
- 費用:
  - 2026-10-28にユーザーが費用合計US$100までを承認した。初回・試料再生成・本生成を同じ累積予算で管理し、各ジョブの最大時間・単価・残額・独立終了経路を記録する。上限額を使い切る計画にはしない。
  - GPU費用の初期5万円以内・本格学習16万〜32万円は初回構想の予算例であり、支出承認ではない。M6の実測で計画を再見積もりする（`docs/COST_ESTIMATE.md`）。費用が発生する操作は、事前承認を得てから行う。
  - Web の維持費は、ほぼ0円を目指す。無料枠の範囲内であることと、永続的に無料であることは区別する。
- 品質: TDD を徹底する。参照実装との一致と変異テストで検証する（ADR-003）。
- 開発経路: 変更前に作業ブランチを作成し、PR と必須 CI を経由する。main への直接 push、force push、削除、保護の bypass は行わない。詳細は `CONTRIBUTING.md`。
- Python: 3.14系を基本とし、依存が未対応の場合のみ3.13系を使う。実行は `uv run --locked`、依存追加は `uv add`、固定値は `.python-version` と `uv.lock`。さらに古い版の採用には、理由・対象・解消条件を記録する。
- セキュリティ: 秘密情報は Secrets や環境変数で扱う。インポートされる入力は、サイズを制限し、全手を再生して検証する。

## フェーズ

| Phase | 名前 | 目的 | ゴールの要約 |
|---|---|---|---|
| 0 | 調査と設計 | ルール・技術・費用の前提をそろえて手戻りを防ぐ | 準拠ルール・構成・設計判断を文書化し、開発環境とリポジトリを準備できている |
| 1 | Rust ルールエンジン | 全実装が同じ正しいルールを使えるようにする | 合法手・状態遷移・終局・棋譜が動き、独立参照実装との照合と変異検出が通る |
| 2 | Web ゲーム Alpha | 三次元盤面を把握・操作し、AI観戦と対局ができる最初の公開版を作る | 公開URLでランダムAI同士の観戦と人間対AIができ、自動デプロイ・配信SHA・公開E2Eを確認できる |
| 3 | 合成データセット | 学習と評価に使える信頼できるデータを用意する | 重複除外後10万局面の生成・全件検証・固定条件の全再生成、対局単位の分割、HF public/manualへの公開と固定revisionのhash照合を確認できる |
| 4 | Transformer-S | 小型モデルで学習から実機ブラウザでのAI観戦までをつなぐ | 学習・評価・再開・変換が通り、評価と同じ配布ファイルの各実行可能版を両AIに選んで観戦でき、人間対AIも利用できる |
| 5 | 自己対局と分散学習 | 自己対局で強くなる学習ループを作り、複数GPUで回す | 複数世代の自己対局ループ、1 GPUと4 GPUの学習、別インスタンスでの再開、世代比較を承認予算内で確認できる |
| 6 | Transformer-M と研究比較 | 三次元空間に適した構造を同じ計算予算で比較する | 比較条件と棋力・学習効率・速度を再現手順付きで公開し、モデル公開とWebでの選択を確認できる |
| 7 | 正式公開 | 一般ユーザーが観戦を楽しめ、研究者が再利用・再現できる形で届ける | 公開URLでAI対局の観戦・モデル比較ができ、補助機能として人間対AIも使え、モデル・データ・生成と学習の再現手順にアクセスできる |

各フェーズの詳細な完了条件・検証方法・進捗は [ROADMAP](ROADMAP.md) を正とする。Phaseは全体の開発段階、M0〜M6は実装順に並べた実行単位（R0はM1前に追加したルール・表示の比較試作）で、番号は対応しない。各Mの目的と具体的な完了条件は [実行計画](ROADMAP.md#実行計画マイルストーン) を参照。リポジトリの構成は `CLAUDE.md`、設計判断は `docs/ARCHITECTURE_DECISIONS.md` を参照。
