# VoxelShogi プロジェクト仕様

## 目的

9×9×9 の三次元将棋（729マス・372枚）を題材に、**再現可能な三次元将棋 AI 研究プラットフォーム**を OSS として提供する。次の要素を一貫して開発・公開する。

1. Rust ルールエンジン（Rust ネイティブ、WASM、Python から同じロジックを使う）
2. 誰でも無料で遊べるブラウザゲーム「VoxelShogi Arena」（Cloudflare）
3. エンジンで生成した合成データセット（Rules / Search / Self-play / Tactical）
4. Transformer ベースの Policy/Value モデル（S: 5–10M、M: 20–35M パラメータ）
5. Vast.ai での 1〜4 GPU 学習環境（DDP、再開可能なチェックポイント）
6. 人間 vs AI、AI vs AI をブラウザ内推論で実行する（GPU サーバーは常時稼働させない）
7. GitHub と Hugging Face（`ayousanz/`）での公開

**新規性について**: 「初めての三次元将棋」ではない。新規性は次の2点にある。

- エンジン・データ・モデル・自己対局・分散学習を、一貫して公開すること。
- 729 トークンの三次元空間に対して、3D-CNN、Full Attention、Axial Attention、Geometry-Aware Attention を、同じ計算予算で比較する研究。

詳細は `docs/RELATED_WORK.md` を参照。

## スコープ

| 含む | 含まない（初期） |
|---|---|
| 人間 vs AI、AI vs AI 観戦、棋譜の保存・再生・共有 | 人間同士の対局（ローカル・オンライン）、マルチプレイ |
| ブラウザ内推論（WebGPU、WASM フォールバック） | サーバー側での常時 GPU 推論 |
| 同一ホストでのマルチ GPU（DDP） | 複数ホストにまたがる分散学習 |
| 独自エンジンで生成した合成データ | 第三者の棋譜の収集・公開 |

対局モードは人間 vs AI と AI vs AI 観戦に限定する。人間同士の対局・マルチプレイは、後続フェーズにも追加しない（2026-10-25 ユーザー指定）。

## 横断的な要件

- すべての棋譜とデータに、`ruleset_id`（現在は `voxelshogi-standard-v1`）を付ける。
- 再現性: 乱数シード、エンジンの Git コミット、生成アルゴリズムのバージョンを保存する。対局単位で train/val/test に分割する。
- 教師ラベルには、出所を区別するメタデータを付ける（ルールによる確定値、探索による推定値、自己対局の統計値）。ランダム AI の手を「最善手」として保存しない。
- Web デモ: 対象の実機のブラウザで、配信用に変換したモデルそのものを動かし、人間 vs AI・AI 観戦で試せるようにする。Web 向けに作成・評価した実行可能な変換版は、採用版・比較版を問わずすべてデモで選択できるようにする。量子化・FP16化などで精度が下がった版も対象とする。モデル名・精度形式・実際の推論 backend を表示し、未対応の実機では理由を示す。
- モデル評価と配信の一致: 変換前の基準モデルと、各変換済みモデルの精度・棋力・速度・サイズを比較する。評価した配布ファイルとデモで読み込むファイルの SHA-256 を一致させ、Model Card から追跡できるようにする（外部データ形式の重みを使う場合は全ファイルを対象にする）。量子化による差と runtime 間の実装誤差は別に検証する。
- 費用:
  - GPU は、初期支出5万円以内から始める。本格的な学習は16万〜32万円を計画値とする（`docs/COST_ESTIMATE.md`）。費用が発生する操作は、事前承認を得てから行う。
  - Web の維持費は、ほぼ0円を目指す。無料枠の範囲内であることと、永続的に無料であることは区別する。
- 品質: TDD を徹底する。参照実装との一致と変異テストで検証する（ADR-003）。
- 開発経路: 変更前に作業ブランチを作成し、PR と必須 CI を経由する。main への直接 push、force push、削除、保護の bypass は行わない。詳細は `CONTRIBUTING.md`。
- Python: 3.14系を基本とし、依存が未対応の場合のみ3.13系を使う。さらに古い版の採用には、理由・対象・解消条件を記録する。固定値は `.python-version`。
- セキュリティ: 秘密情報は Secrets や環境変数で扱う。インポートされる入力は、サイズを制限し、全手を再生して検証する。

## フェーズ

| Phase | 名前 | 目的 | ゴールの要約 |
|---|---|---|---|
| 0 | 調査と設計 | ルール・技術・費用の前提をそろえて手戻りを防ぐ | 準拠ルール・構成・設計判断を文書化し、開発環境とリポジトリを準備できている |
| 1 | Rust ルールエンジン | 全実装が同じ正しいルールを使えるようにする | 合法手・状態遷移・終局・棋譜が動き、独立参照実装との照合と変異検出が通る |
| 2 | Web ゲーム Alpha | 三次元盤面を把握・操作してAIと遊べる最初の公開版を作る | 公開URLでランダムAIとの対局・AI観戦ができ、自動デプロイ・配信SHA・公開E2Eを確認できる |
| 3 | 合成データセット | 学習と評価に使える信頼できるデータを用意する | 約10万局面の生成・全件検証、固定条件での再生成、対局単位の分割、公開準備ができる |
| 4 | Transformer-S | 小型モデルで学習から実機ブラウザ対局までをつなぐ | 学習・評価・再開・変換が通り、評価と同じ配布ファイルの各実行可能版で対局・観戦できる |
| 5 | 自己対局と分散学習 | 自己対局で強くなる学習ループを作り、複数GPUで回す | 複数世代の自己対局ループ、1 GPUと4 GPUの学習、別インスタンスでの再開、世代比較を承認予算内で確認できる |
| 6 | Transformer-M と研究比較 | 三次元空間に適した構造を同じ計算予算で比較する | 比較条件と棋力・学習効率・速度を再現手順付きで公開し、モデル公開とWebでの選択を確認できる |
| 7 | 正式公開 | 一般ユーザーが遊べ、研究者が再利用・再現できる形で届ける | 公開URLで対局・観戦でき、モデル・データへアクセスでき、公開手順から生成・学習を再実行できる |

各フェーズの詳細な完了条件・検証方法・進捗は [ROADMAP](ROADMAP.md) を正とする。Phaseは全体の開発段階、M0〜M6は実装順に並べた実行単位で、番号は対応しない。各Mの目的と具体的な完了条件は [実行計画](ROADMAP.md#実行計画マイルストーン) を参照。リポジトリの構成は `CLAUDE.md`、設計判断は `docs/ARCHITECTURE_DECISIONS.md` を参照。
