# M1 実装計画: 探索AI（Rust）

更新: 2026-10-26。**M1完了。PR #10の最終必須CI・通常取り込み・公開後検証が成功。** Rust150件、既知変異21件、全1,172変異の分類、独立参照探索とNative計測を確認した。 M0は取り込み・公開後検証まで完了し（[記録](M0_VALIDATION.md)）、R0のルール・観戦試作も完了した（[実測](NINE_KINGS_EXPERIMENT.md)）。本書は実装手順と完了条件を示す。

## 目的と範囲

Webで探索AI同士の対局を観戦し、後の教師データ生成でも共用する CPU 探索を `voxelshogi-core` に作る。人間対AIにも同じ探索を使う。まず駒得評価と αβ探索を正しく実装し、固定深さ・固定ノード数で再現できるようにする。WASM の公開 API・Web Worker・観戦 UI は M2、モデル推論は M3、学習は M6 で行う（[全体計画](ROADMAP.md#実行計画マイルストーン)）。

標準には検証付きの `GameState::apply_move` とprivateな `make_unchecked` がある。R0には9王の `CaptureGame::after_generated` と、標準対照にも使う `experiment` の幅制限探索がある。これらの適用・評価・αβ・再生検証を調べ、再利用範囲を決める。標準1王のM1探索を `search` に実装した。通常画面のライブAIはランダムのまま、比較室はR0の生成済み棋譜を再生する。ライブ探索はM2で追加する。

本計画は現行の `voxelshogi-standard-v1` を前提とする。[複数王ルールの調査](RULE_VARIANTS_RESEARCH.md) の候補を採用する場合は、ルールID・終局・評価・戦術テストの仕様を更新してから実装する。観戦を主目的とすることは確定しているが、9王・5先取の正式採用は未決定。R0の400／800手・探索幅の感度を踏まえ、採用ルールと上限を記録する。9王を採用する場合は、詰みの代わりに王捕獲目標・規定手数採点・終局優先順位の戦術と評価を定義する。

各段階で独立した期待値のテストを先に書き、RED、最小実装、正常系、変異の検出を確認する。[開発手順](../CONTRIBUTING.md) に従って変更前に作業ブランチを作り、段階ごとにレビューできる PR にまとめる。以下の7段階は実装順であり、PR の数や所要時間の確約ではない。

## 実装順と検証

| 1 | 合法手を前提にした探索用の適用経路 | 固定 seed のランダム対局の全手で検証付き適用と一致。捕獲・成り・駒打ち・両色・繰り返しの明示局面も含める |
| 2 | 手番側から見た駒得評価 | 盤上・持ち駒・成駒の値を仕様として定義し、手計算と一致。手番反転と両色の対称性も検証 |

| 4 | 戦術と結果の契約 | 1手詰め、深さ2以上での駒損回避、合法手だけの応答、終局時の手なし、両色の勝敗・引き分けを検証 |
| 5 | 手の並べ替え・反復深化・置換表 | 機能の有無で同じ完了深さの評価値が一致。固定した比較局面でノード数削減を確認し、各機能を切り分けて検証 |
| 6 | 深さ・ノード・時間の上限と再現性 | 予算切れを明示し、未完了の深さを採用しない。固定条件で同じ結果、時間上限で停止して合法に応答 |
| 7 | release 計測と文書更新 | 固定局面でノード/秒・到達深さ・時間・設定を記録し、エンジン文書・ROADMAP・費用見積もりに反映 |

### 1. 状態遷移と 2. 評価

検証を省く適用経路は、同じ局面から生成した合法手だけを渡す内部契約にする。外部入力に対する合法性検証は既存 API で行う。比較では盤面・持ち駒・手番・手数・ハッシュに加え、続く合法手と終局結果も確かめ、千日手・連続王手の履歴が保持されることを確認する。既存適用との比較に加えて、捕獲・成り・駒打ちは手書きの期待値でも検証する。

駒価値の具体値と整数の範囲は段階2で決め、テストの期待値とともに記録する。標準では王の捕獲を詰み評価の代用にしない。9王では仕様どおり捕獲数と目標到達を評価し、王を持ち駒にしない。終局の勝敗評価は取り得る駒得より優先し、手番側の符号と、早い詰みを優先する場合の距離の扱いを明文化する。

### 3. 参照探索と 4. 戦術

参照 minimax はテスト内で全合法手を素朴に読み、製品の枝刈り・置換表・並べ替えを共有しない。状態遷移には検証付き API を使い、静的評価と終局の期待値には手計算の局面も置く。既存ルールの終局判定を使い、千日手・連続王手を探索側で別解釈しない。呼び出し元が終局済みにした最大手数などの結果も尊重する。

同点手の順序は、移動元・移動先・成り・駒打ちの種別を含む明示的な規則として定義する。`legal_moves` の列挙順はバージョン間の契約ではないため、その順序だけに依存しない。最適化前後はまず評価値で比較し、複数の最善手がある局面では返却手が最善手集合に入ることを確認する。同じ探索設定での再実行は同じ手になることも検証する。

### 5. 最適化と 6. 上限

- 置換表は深さと EXACT / LOWER / UPPER の境界を区別する。浅い値を深い探索の確定値として使わず、中断結果を確定値として保存しない。
- 同じ盤面ハッシュでもルールID・上限・千日手や連続王手の履歴が違えば結果が変わり得る。履歴を含むキーや再利用の制限を設計し、異なる履歴を持つ局面で誤った再利用を拒否するテストを置く。手数に依存する制限・詰み距離の値も再利用時に整合させる。
- 反復深化は最後に完了した深さの結果を採用する。深さ0・ノード0などで未探索でも、非終局なら明示した順序による合法な代替手を返す。終局なら手なしとする。ノード数の定義、上限を数える位置、停止理由を API と文書に揃える。
- 再現条件はエンジンコミット・局面と履歴・評価設定・探索設定・置換表の初期状態を含める。固定深さ/ノードのテストと、時計に依存する停止テストを分ける。時間だけを同じにしても環境負荷で到達深さが変わるため、同じ手は保証しない。
- ノード削減は効果の出る固定局面で確認する。反復深化の浅い反復や並べ替えには追加処理があるため、すべての局面・機能で総ノード数が必ず減るとは扱わない。最終深さと反復全体のノード数を分けて記録する。

## CI と計測

各 PR で変更に関連する Rust テスト・fmt・Clippy を実行し、必須7チェックの成功後に取り込む。PR CI は小さな固定局面を使い、約1秒で特定深さへ到達することを一律の合否条件にしない。追加テストには、そのバグを注入したときに失敗する証拠を残す。core の探索実装を全体変異調査にも含め、既存ファイルを変更した場合は同値変異のソース指紋と根拠を再確認する。全体調査の結果・未分類の生き残りを確認して M1 を閉じる。

既存の初期局面424合法手・生成1.18ms・ランダム対局約1,500手/秒は **Apple M1 CPU の2026-10-25実測**で、探索ノード/秒ではない。M1は単独releaseで初期局面の深さ2を約0.33秒、1秒上限3回でいずれも深さ2の完了を確認した。[計測・全体検証の記録](M1_VALIDATION.md)。R0の幅制限・並行実行の値とは分ける。

段階7では CPU・OS・Rust版・エンジンコミット、局面と履歴、深さ/ノード/時間上限、置換表と並べ替えの設定、ノード数・完了深さ・経過時間・ノード/秒を保存する。正しさのテストと性能計測を分け、最適化の比較には同じ条件を使う。Normal の約1秒の予算はまず目安として測り、M2 で対象ブラウザの WASM/Worker でも再計測して決める。

M1 の CPU 計測は M4 のデータ生成時間の見積もりに使う。GPU の学習費用は M6 の学習スループットで見積もり直す（[費用見積もり](COST_ESTIMATE.md)）。M1 で有料 GPU は使わない。

## 実装した探索の契約

- `search::search(&GameState, SearchLimits, SearchOptions)` は標準1王ルール専用。R0の探索・棋譜を変更せず、9王の正式採用も行わない。
- 全合法手を対象にαβ探索し、`SearchOptions` で反復深化・手の並べ替え・置換表を独立に切り替えられる。候補幅による手の省略は行わない。
- 駒価値（歩=100）は歩100・香300・桂320・銀450・金550・角800・飛1000・王0・金相当の成駒550・馬1100・竜1300。持ち駒は未成駒の値。手番側の駒得を返し、終局の勝ち／負けは±1,000,000、引き分けは0。詰み距離の加点は行わない。
- 深さは0〜64、置換表容量は0〜1,000,000件。ノードは入った局面を根・葉・置換表ヒットも含め1件とし、反復全体で上限を共有する。根の終局確認・代替合法手の取得は探索ノードに数えない。
- 未探索・中断時も非終局なら合法な代替手を返す。未完了の反復の評価は公開せず、完成した反復がなければ `score=None`。深さ0を完了した場合は静的評価。終局は深さ・予算より優先し、手なし・終局評価・`Terminal` を返す。
- 時間上限は各ノード直前に確認するsoft deadline。進行中の合法手生成など1処理分は超過し得る。`search_with_clock` は経過時間を注入でき、WASMの時計アダプタと停止の決定的テストに使う。
- 任意の絶対ゲーム手数上限は `max_game_ply` で指定する。自然な終局を優先してから、上限到達を引き分けにする。盤外の手数打ち切りを使う呼び出し側はこの値を渡す。
- 置換表は呼び出しごとに新規作成。標準ルール・評価を固定し、局面ハッシュ・**同じ探索深さ**・ゲーム上限までの残り手数をキーにする。履歴内の同一ハッシュの最大出現数＋残り探索深さが4未満の場合だけ履歴を省略して利用する。それ以外は得点の再利用を止め、千日手・連続王手を跨ぐ誤用を防ぐ。EXACT/LOWER/UPPERを区別し、中断ノードを保存しない。
- 並べ替えは前回の完了反復の最善手、捕獲・成りの駒得、`Move` の全順序の順。機能無効時は `Move` 順。同評価ではその順の最初の手を保つ。列挙順や乱数に依存しない。
- Native計測用CLIは `cargo run --locked --release -p voxelshogi-core --example search_bench -- FULL_ENGINE_SHA`。実装ソースと指定コミットが一致しなければ拒否し、環境・設定・ノード数・時間・完了深さをJSONで記録する。計測結果の保存は全体検証と合わせて行う。
