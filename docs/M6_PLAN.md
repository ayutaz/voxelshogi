## M6-0で先に決めること

- 現在の代表モデルは5,021,064パラメータ、入力43ch、Policy 1,067,985、Valueは手番側のscalar tanh。過去案の勝ち／引分／負けの3出力へ暗黙に変えない。学習用batchとブラウザ用batch1のexportを区別する。
- `duplicate_of != null`を学習・評価から除外する。Policyの最善手教師は`teacher_valid=true`かつ有効な探索結果だけを対象とする。random／rulesの着手や、序盤分岐中の`played_move`を探索推奨手にすり替えない。
- 探索scoreは駒得／終局の尺度であり勝率ではない。Valueの教師の出所・手番の視点・正規化・終局値・有効条件を最初の学習前に固定する。64手で打ち切られた対局を引分や実際の勝敗ラベルへ変換しない。
- 全有効局面数と学習可能な探索教師数を分ける。本生成の10万有効局面が、そのまま10万件の最善手教師になる計画ではない。各splitの実際の教師数と評価に使える件数を確認する。
- 同一対局・同一局面の漏洩を防ぎ、testを学習・モデル選択・量子化の調整に使わない。比較するseed・初期局面・先後・探索予算・手数上限・中断再開の数値一致基準を、測定前に文書化する。
- 最初のValue教師は検証済み探索scoreの`tanh(score / 1000)`に固定した。[教師・損失・評価契約](M6_TRAINING_CONTRACT.md)で終局尺度・評価条件も定義する。静的`evaluation`や実勝敗との混在を暗黙に行わない。Policy・Valueの有効件数、教師の完了深さ、除外理由を別々に出力する。
- 1,067,985行動の密なマスク・特徴量を全件分RAMへ展開しない。分割読み込みとbatch単位のマスクを使い、batchサイズ・精度・勾配累積の採否は実VRAMで判断する。ブラウザ互換性のためにモデルを無記録で縮小しない。

## 外部GPU試行から本学習への判断

1. **起動前**：上記の実装・CI、実データ検査器、checkpoint保持先、GPU/ブラウザ環境の準備を完了する。CloudRiftを第一候補、Vast.aiを代替として現行の単価・空き・追加保存費を確認し、最大時間と総額を提示する。
2. **M6-2の冒頭**：固定HF revisionの承認済みファイルを取得・hash照合し、split別・完了深さ別の実教師件数、非空のtrain/val/test、履歴・行動契約・除外条件を確認して入力manifestを凍結する。件数や契約が合わなければ学習前に停止する。
3. **少量CUDA学習**：実GPUとCUDA対応を確認し、同じモデル・固定条件でloss、step/s、局面/s、GPU使用率、VRAM、RSS、起動・転送・保存時間を測る。checkpointを保存・再読込して継続し、CPU CIでの一致とCUDAの事前許容誤差を区別する。対象LinuxブラウザのWebGPUが実GPUを使用できるかも先に確認する。
4. **試行終了**：再開用checkpointを外部へ退避し、hashと復旧可能性を確認して実機を終了する。遅さ・OOM・不一致は失敗記録として保持し、実機は終了する。上限を自動で緩めない。本学習のstep数・epoch数・評価対局数・最大総額はこの実測から決める。
5. **M6-3**：見積もり確定後に本学習し、valで選択したモデルを固定testと先後を入れ替えたRandom／M1探索との対局で評価する。勝敗・打切り・信頼区間を記録する。強さが改善しなかった場合も結果を残し、追加試行の条件・費用を再判定する。

GPUによる**学習計算を始めるのはM6-2**。その冒頭のデータ監査は同じGPUサービスのCPUで行い、別の常時稼働サーバーを持たない。GPU時間・本学習費・完了日はいまは未確定で、M4のCPU生成時間から換算しない。

## GPUサービス・依存・費用

CloudRiftを第一候補、Vast.aiを代替とする。M4で使ったRTX5090構成はCPU生成の実績であり、CUDA学習の動作・速度・VRAM余裕の実績ではない。小規模試行前に空き・価格・GPUアーキテクチャ対応・CUDA版PyTorchとdriverの互換性を確認する。空きがなくてもMacで学習へ切り替えない。

Python3.14を基本とし、CUDAの必須依存が未対応の場合だけ3.13を使い、対象・理由・解消条件を記録する。依存は`uv add`とlockで管理する。現在のLinux CI用CPU版torchを維持し、[外部CUDA用のPython3.14.9／torch2.14.1+cu130の別lockと検査器](M6_CUDA.md)を準備中。依存の固定で実GPUの動作確認を代用しない。

**実GPU試行と本学習は未実行。初回試行は最大4時間／US$4で承認済み。** 2026-10-29の個別承認で、既存US$100内のM6基本枠はUS$24。不足時の追加GPU予算US$100も承認済みで、実測見積もりで不足を記録した場合に使う（M6最大US$124、全体最大US$200）。追加枠はまだ有効化しておらず、現在の起動制御は基本枠を守る。[承認記録](../export/m6-approval.json)。試行実測から本学習・評価・転送までの時間と費用を算出する。GPUを常時稼働させず、M4終了後の再レンタルも含めて計画する。

計算・評価・変換・公開stagingと転送は外部Linux。データと学習checkpointはMacへ中継しない。HFへ公開する推論用重み・カードと、optimizer等を含む再開状態は別repoにする。再開状態はJSON＋safetensorsへ変換し、public/manual・Community OFFで公開する方針を個別承認済み。実行用のpickle checkpointは公開しない。Macに置くモデルは必要な実機検証用だけにする。

再開用保存先の第一案は同サービスの永続volumeだったが、[現行API調査](M6_CUDA.md#費用保持先の調査)では対応種別がなく、使える前提にしない。保存先は承認済みの別HF repo `voxelshogi/voxelshogi-transformer-s-training-state`。latest/bestと履歴を再現実験用に保持し、新規アップロードは履歴分を含め累積1 GiB以下、有料保存追加なし。固定revisionの全hashと新しいrunへの復旧を確認する。エフェメラルディスクだけに唯一のcheckpointを残して実機を終了しない。[保存・費用の確定方針](M6_RUN_PROPOSAL.md)。HF認証情報の送信・公開操作は既存の継続承認を使い、実機IDが変わるたびに再確認しない。

## HF取得ゲートと公開デモ

学習済みモデルは`voxelshogi/`配下・public/manual・Community OFFで公開し、Model Cardにデータrevision・教師条件・学習設定・評価と各変換版の制約を記載する。M6の対象学習済みモデルと再開状態のApache-2.0は2026-10-29に個別承認済み。M4のCC-BY-4.0・固定revision・帰属もCardへ記載する。

手動取得承認とブラウザデモを両立する配信方法をM6-0の契約で固定した。取得承認済みの利用者がHFから取得した変換モデルをデモへ読み込み、公開manifestのhashを確認して選択する方式とする。読込・Worker・対局制御は取り込み済みで、[モデル選択UI・条件付き棋譜・実ONNX E2E](M6_ARENA.md)を追加して検証する。実学習済みモデルと実GPUの検証は未実施。HFの書き込み資格情報をブラウザへ埋め込まず、別の公開URLへ重みを複製してゲートを迂回しない。

量子化等で精度が下がった版も、実行可能なら比較版として同じモデル選択から触れるようにする。未対応の形式×backendは理由を表示する。M3のFP16×M1 WebGPUは基準未達であり、M6でも未検証のまま対応済みにしない。WASMや別形式へ暗黙に置換しない。

変換時は[評価した学習済みcheckpointから3形式を作る処理](M6_EXPORT.md)を準備中で、校正や調整にはtrain/valだけを使う。各形式の精度・棋力・サイズ・速度を同じ事前条件で比較する。デモは利用者が取得したモデルフォルダーをブラウザで選び、実ONNXと同形式の照合入力／出力について形式・model ID・SHA-256を検査してWorkerへ渡す。両AIのモデル選択、描画中の推論、中断・切り替え時の解放を実ファイルで検証する。公開の探索AI観戦とM3の承認済み配布は維持する。

実機WebGPU／WASMの計測は、GPUサービス上のLinuxと実GPU対応ブラウザを第一候補とする。CIのSwiftShaderやM3当時のM1結果を、M6学習済みモデルの実機結果に流用しない。Macを重い計測の代替にせず、未検証の端末・backendへ対応を一般化しない。
