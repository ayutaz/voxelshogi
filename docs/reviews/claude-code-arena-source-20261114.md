# VoxelShogi 新UI/UX・状態管理 レビュー（ソースのみ）

ソースから確定できた「重大」はありません。中が7件、軽微が8件です。`ArenaController` と `model-library` はbundleに無いため、その動作に依存する件は前提を明記しています。画像の確認も実ブラウザでの操作もしていません。コードは変更していません。

## A. ソースで確認した指摘

### 中

**1. 人間対AIで履歴を見て末尾に戻ると、AIが止まったままになる可能性**
- 場所：`App.tsx:247`、`:107-115`、`:303`、`:123-135`
- 操作：h-rで「◀ 1手戻る」を押し、「1手進む ▶」や「末尾へ戻る」、棋譜クリックで末尾に戻ってから自分の手を指す。
- 問題：`goto` は毎回 `pause()` を呼び、`running=false` になります。末尾に戻っても `true` に戻すのは「再開」ボタンだけです。対局中にAI設定を変えたときも、`reset()` の後に `pause()` が呼ばれ、新しい対局が停止状態で始まります。AIが `running=false` では指さない作りなら、AIが応答しないまま「一時停止中」と表示されます（h-rの `reset` が `running=true` にしていることから、その作りの可能性が高いです）。
- 修正案：人間対AIでは、閲覧位置が末尾に戻ったら自動で再開する。または人間モードでは履歴操作と進行停止を分ける。

**2. 人間対AIの履歴表示中、案内文と実際の操作が合わない**
- 場所：`App.tsx:233`、`:65`、`:285`
- 操作：h-rで過去の局面を表示する。
- 問題：「履歴表示中：1手指すと分岐します」と出ますが、`humanTurn` は `ply===moveCount` の時だけ真なので、盤は操作できません。分岐するには「この局面から対戦を分岐」を押す必要があります。
- 修正案：モードごとに文言を分ける。例：「履歴を表示中。分岐するには『この局面から対戦を分岐』」。

**3. 分岐に確認も取り消しも無く、それ以降の手が画面から消える**
- 場所：`App.tsx:248-263`、`:297`、`:303`
- 操作：AI観戦中に過去の局面で、同じ位置のボタン（ラベルが「1手指す」から「ここからAIで分岐」に変わったもの）を押す。またはh-rで「この局面から対戦を分岐」を押す。
- 問題：`allowReplacement` を通らず、それ以降の手が即座に切り捨てられます。元の対局はD1に中断として残りますが、端末に全棋譜を保存する手段は無くなります。
- 修正案：分岐の前に、新規対局と同じ置換確認を入れる。

**4. 人間が1回クリックすると、以後AIの着手層を追わなくなる**
- 場所：`App.tsx:144-151`、`:59`
- 操作：h-rで駒を1回クリックしてから指す。
- 問題：`manualView()` で `follow=false` になり、自動では戻りません。AIが別の層に指しても2D断面は切り替わらず、AIの着手を見落としやすくなります。
- 修正案：人間の着手が終わったら追従の状態を元に戻す。または、クリック時は選択中の表示だけを一時的に固定する。

**5. 「学習済みS」を対戦の開始画面から選ぶと、モデル条件が欠けるおそれ**
- 場所：`App.tsx:244`、`:311`、`:130-134`、`agents.ts:13`
- 操作：モデルを読み込んだ後、そのモデルを座席に割り当てないまま「AIと対戦」で「学習済みS」を選んで開始する。
- 問題：`selectDifficulty` と違い、`startMatch` は `library.choices` を補完しません。choicesが空なら `collectionAgents` が例外を投げ、その対局は1手も保存されません。AIの側も、モデル未設定のまま開始されます。
- 前提：`addModel` が両座席のchoicesを自動で設定するかは未確認です。この件はその前提で成り立ちます。
- 修正案：開始時にchoicesを補完するか、モデルが未選択なら開始できないようにする。

**6. 初回の設定取得に失敗すると、そのセッションの対局が保存されない**
- 場所：`automatic-client.ts:32-45`、`:63-67`
- 操作：ページを開いた瞬間に `/api/collection` か `/build-info.json` が一時的に失敗する（モバイル回線など）。
- 問題：`enabled` が二度と `true` にならず、取得の再試行もありません。以降の全対局が保存されず、stagedに積まれた最大8件も送られません。
- 修正案：設定取得を間隔をあけて再試行し、成功したらstagedを送る。送信の状態は画面に出さないままでよいです。

**7. 分岐した直後に、元の対局の途中までが別の対局として保存される**
- 場所：`App.tsx:252-253`、`automatic-client.ts:59`
- 操作：分岐ボタンを押すだけで、新しい手は指さない。
- 問題：`importRecord` によって元の手順を含む新しいgameIdのv1が即座に送られます。分岐元のIDや分岐点は記録に残りません。結果として、同じ手順が親子2件に入り、区別できないまま日次1,000件の枠も消費します。
- 修正案：分岐後の最初の実着手まで保存を遅らせる。分析で親子を区別する必要があれば、親のgameIdと分岐手数を保存項目に加える（schemaの変更になります）。

### 軽微

- **観戦の開始画面でAI条件が分からない**（`App.tsx:312`、`:273`）：「現在の先後AI設定で」とだけ表示され、どのAI同士の対局になるか見えません。人間対AIの後に観戦すると、前に選んだ相手がそのまま残ります。観戦中は「AIを観戦」タブを押しても何も起きません。
- **投了が設定シート内にあり、確認も無い**（`App.tsx:317`）：押すと即座に終局し、finishedとして保存されます。
- **「同じ設定でもう一局」で観戦が始まらない**（`App.tsx:165`、`:305`）：観戦モードでは `reset` が `running=false` にするため、`startMatch` と挙動が揃っていません。
- **狭い画面で元／先の層が分からない**（`styles.css:6`、`App.tsx:279`）：720px以下では `.layer-rail` が非表示になり、層の `<select>` にも元／先の表示がありません。直前手の文字表示にしか残りません。
- **分岐に失敗すると収集IDだけが先に切り替わる**（`App.tsx:252-254`）：`begin()` が `importRecord` より先に呼ばれます。失敗すると旧IDは中断扱いになり、同じ対局がその後新しいIDで保存されます。
- **上限による429も再試行される**（`automatic-client.ts:107`、`receiver.ts:71`）：日次上限のように時間で解消しないエラーでも約40秒再送し、その間は他の対局の終局保存も待たされます。
- **後手から始まる棋譜だと先後の表示が逆になる**（`App.tsx:280`、`Panels.tsx:98`）：`ply%2` で先後を決めているためです。持ち駒ボタン（`Panels.tsx:21`）も `humanTurn` を見ず、AIの手番でも押せる見た目になります。
- **「モデル」シートに対局設定がまるごと入っている**（`App.tsx:315`）：モード変更・新規対局・投了まで含まれ、「対局設定」とほぼ同じ内容になっています。

### ソース上は問題なしと確認した点

- **import除外**：`ownedRecord=false` を設定してから置換し、その後 `begin(false)` を呼ぶ順序になっています。
- **巻戻り防止**：サーバー側で、古いversionの無視、着手列が延長であることの検査、終局後の固定が行われています。
- **モデル条件の固定**：最初の実着手の時点で固定されます。
- **取消**：開始・モード変更・importの確認をキャンセルすると、対局が保持されます。
