## 2. 指摘（重大度順）

ソース上で、P0（初見がモデルなしで開始・停止・送りをできない）に当たる経路は見つかりませんでした。初期状態はAI対AIで停止中です（`App.tsx:35-36`）。「観戦を開始」を押すと`running`がtrueになり、`arena-controller.ts:84-94`で探索が予約されます。ただし実際に動くかどうかは未確認です。

### N1【P1・実ブラウザ確認が必要】「1手指す」を押すと、自分自身が無効化されてキーボードfocusが失われる恐れ
- **場所**：`App.tsx:338`（`aiStatus.phase === 'waiting'`のとき無効）、`arena-controller.ts:106-110,181`（`step()`から同期的に`publish('waiting')`が呼ばれる）
- **再現**：Tabで「1手指す」へ移動してEnterを押す。直後にwaiting/thinkingの状態になり、ボタンが`disabled`になる。focus fixupが働くブラウザでは、focusが`body`へ移る可能性がある。そうなると、次のTabはページ先頭から左パネル経由で始まる（N4）。キーボードで「連続して送る」操作が成り立たない恐れがあります。
- **最小修正**：処理中は`disabled`をやめて`aria-disabled="true"`にし、クリックを無視する。`step()`は既に二重実行をはじく作りです（`arena-controller.ts:108`）。同じ現象は、端に達した「◀1手戻る／1手進む▶」（`App.tsx:240,243`）と、終局時の開始ボタン（`App.tsx:332`）でも起きます（こちらはP3）。

### N2【P1・推定】直前手の表示と盤の下側が、最初の画面の外に出る可能性
- **場所**：盤より上に説明（`App.tsx:325-329`）、再生操作（`App.tsx:330-361`）、表示切替（`App.tsx:362-364`）、後手の持ち駒（`App.tsx:370`）が並ぶ。直前手の表示は盤の下（`App.tsx:376-381`）。CSSは`styles.css:49-53,70,78-80`と`styles.css:116-127`
- **再現（概算）**：
  - 1440×900：ヘッダー約45px、説明約90px、再生パネル約180px（解析表示3行を含む）、表示切替約50px、持ち駒約36px、2D盤約500px（46pxのマス×10行＋題名）。合計が900pxを超えるため、直前手の表示はスクロールしないと見えない見込みです。
  - 390×844：盤が始まるのは約490pxの位置からと推定され、盤の下半分と直前手の表示が画面外に出る見込みです。
- **影響**：2D既定のまま追従ONにすると、着手のたびに盤全体が別の層に切り替わります。どの層を見ているかの手がかりは、小さな題名（`Board2D.tsx:35`）だけです。どの手が指されたかの説明が画面外にあると、「盤面が丸ごと入れ替わった」と受け取られる恐れがあります。
- **最小修正**：直前手の1行（`App.tsx:377`）を再生パネルの中、または盤の題名へ移す（例：`VII層 — 直前手 ☗5七VI→5六VII`）。対局開始後は説明を折りたたむ。3サイズのスクリーンショットで確定してください。

### N3【P2】2D既定では、異層の着手の移動元と軌跡が見えない
