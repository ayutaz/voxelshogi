# spectator-mockup.html レビュー（コード点検のみ）

`spectator-mockup.html` を Read で読み、比較のため `current-390.png` と `current-1440.png` を見ました。モックを描画したり操作したりはしていません。以下では、**[コード]** はHTML/CSS/JSから推論したこと、**[画像]** は既存のスクリーンショットで実際に見えたことを指します。モックの描画結果はどこにも見ていません。

## 検証できる良い点

- **[画像]** 現行の390幅は縦2853pxあります。盤の直後に送信同意のブロックがあり、その下に対局設定と表示設定が続きます。表示切替のボタンも「2D断面/立体で見る/立体と断面」と「3D+2D/3D/2D」の二重です。**[コード]** モックでは表示切替が2つに絞られ、設定とデータは dialog に移っています。主役が観戦であることがはっきりしました。
- **[コード]** 移動元と移動先が、色以外の手がかりでも区別できます。3Dでは点線の円と、実線の円＋「着地」ラベル。2D断面では点線枠と、太枠＋塗り。層レールには「元/着」の文字。説明文には「VII層からVI層へ」と出ます（`:32-37`）。参考棋譜の6手には、層をまたぐ手（3手目と6手目）と同じ層の手の両方が入っています。
- **[コード]** dialog は `showModal()` で開き、開くと「閉じる」にフォーカスし、閉じる時もEscでも元のボタンへフォーカスを戻します（`:41-42`）。自動再生で描画し直しても、レールや棋譜のフォーカスを元に戻しています（`:34,37`）。
- **[コード]** データ周りは「端末へ保存」と「送信同意」が分かれています。送信は既定でOFF、フッターに常に状態が出て、新しい観戦では同意がリセットされます。「未接続」も明記されています。

## 本番前に直すべき点（優先順）

**1. 【最優先】観戦・履歴・終局の状態が1つの `cursor` に混ざっている** **[コード]**
- 「履歴を確認」と「一時停止」は表示がまったく同じです。どちらも「一時停止 · n手目」と「この局面から再生」になります（`:34,42`）。
- 再生中は前後送りが無効で、棋譜をクリックすると `stop()` で観戦そのものが止まります（`:34,39`）。本物のAI対局では「過去の局面を見ている間もAIは指し続けるのか」がこのモックでは決まっていません。
- 終局後も前後送りが無効です。棋譜をクリックすると `ended=false` になり、終局の表示が消えます（`:38`）。
- 「端末へ保存」は `moves.slice(0,cursor)` を保存します（`:41`）。過去の局面を見ている時に押すと、棋譜が黙って途中で切れます。
- 提案：
  - 「対局の状態（進行中/停止/終局）」と「表示位置（最新/n手目）」を別の状態として持つ。
  - 「最新へ戻る」ボタンと「n手目を表示中・対局は進行中」の表示を付ける。
  - 終局後も結果を残したまま振り返れるようにする。
  - 保存は既定で全手を対象にする。
  - 「この局面から再生」の意味を決める（あとの手を捨てるのか、分岐するのか）。

**2. PCの初期表示と狭い幅のレイアウト**
- **[コード・概算]** ステージは `clamp(360px,100svh-310px,590px)` です。1440×900なら590pxになります。上部（designbar・masthead・intro・stagehead）は合計約280pxと見積もりました。これに movebar の76pxを足すと、「観戦をはじめる」がある transport は初期表示の下端あたりか、その外に出る可能性が高いです。ブラウザのUI分だけさらに不利になります。実際の描画で確認が必要です。
- **[コード]** PCで2D表示にすると、メインの盤とサイドバーのミニ盤が同じ断面になり、重複します。
- **[コード]** 360px以下では着手間隔を選ぶ欄が `display:none` で消え、代わりの操作がありません。
- **[コード]** 狭い幅では select が11〜12pxです。iOS Safari では16px未満の入力欄にフォーカスすると画面がズームする挙動が一般に知られていますが、実機では確認していません。

**3. タッチ領域** **[コード]**
- 層レールは、狭い幅の3D表示で 35×27px（間隔1px）、2D表示で 34×30px です。
- 棋譜の行、フッターのボタン、designbar の select は32px程度です。
- 「着手を追う」のチェックボックスは19pxで、ラベルの行もほぼその高さしかありません。
- 34〜35px幅のレールに「VIII 着」を9pxの文字で入れているので、折り返しやはみ出しの恐れがあります。
- 提案：層の選択と追従のON/OFFは44px以上の行にする。レールは前後ボタン付きの切替にすることも検討できます。

**4. 層移動の元/先の情報が一部で欠ける** **[コード]**
- レールの `aria-label="VI層を見る"` が見えている「元/着」の文字を上書きするので、読み上げでは元と着が伝わりません。
- 層をまたぐ手を2Dで見ると、表示中の移動先の層には移動元が描かれません。説明文にしか出てこないので、盤上に「VII層から」のような目印を入れることを提案します。
- 狭い幅ではサイドバーの「この一手を見る」が非表示です。
- 「この層の断面」シートには「層を変えると追従OFF」と書いてありますが、シートの中に層を変える操作がありません（`:41`）。

**5. dialog・キーボード操作とデータ同意の細部** **[コード]**
- どの dialog を開いても `stop()` で観戦が止まり、閉じても再開しません。設定やデータの dialog でも止まる理由が画面上で分かりません。
- 再生/停止・前後送りのキーボードショートカットがありません。
- 終局後は同意のチェックボックスが無効になりますが、理由が書かれていません（`:41`）。
