## 4) 対局データ保存の結論と根拠

**結論：ソースには、棋譜や操作イベントをCloudflare（やその他のサーバー）へ送信・保存する実装は見つかりませんでした。** ただし、ダッシュボード側の設定（Web Analyticsの自動挿入、Logpushなど）はソースからは判断できず、本番に存在しないとは断定しません。

**根拠（ソース）**
- **ネットワーク呼び出しはすべて取得（GET）で、本文の送信なし**：`fetch`の使用箇所は`App.tsx:142`（`/build-info.json`）、`local-model.ts:58`（`/models/m6/catalog.json`）、`inference/runtime.ts:9`と`assets.ts:36`（モデルラボ用のファイル取得）、`ExperimentViewer.tsx:74,157`です。`method`や`body`の指定、`sendBeacon`、`XMLHttpRequest`、`WebSocket`、`EventSource`、analytics系の文字列はGrepで0件でした。`ExperimentViewer`はどこからもimportされておらず、`main.tsx`から到達しません。
- **棋譜はブラウザ内にとどまる**：`recordJson`は`postMessage`で同じページの**Web Worker**（探索・推論）へ渡るだけです（`search-client.ts:49`、`policy-client.ts:55`）。保存は`Blob`のダウンロードのみです（`App.tsx:125-132`）。`localStorage`、`sessionStorage`、`IndexedDB`、Cache APIの使用もありません。
- **配信は静的のみ**：`wrangler.jsonc`は`assets`だけで、Workerスクリプトはなく、KV・R2・D1・Durable Objectsのbindingもありません（`docs/DEPLOYMENT.md:11`も「Worker スクリプトはない」と記載）。`_headers`にもanalytics関連の設定はありません。
- **文書の紛らわしい箇所**：`docs/DEPLOYMENT.md:128`の「実Workerが保存した棋譜」は、E2Eテストでブラウザ内のWorkerがダウンロードさせた棋譜の再検証を指しています。Cloudflareへの保存ではありません。

**HTTPアクセスログ・集計との区別**
- 通常のアクセス記録（URL、IP、User-Agent、時刻など）は、Cloudflare側に一般的なリクエスト集計として残り得ます。URLに棋譜は含まれないので、**再生できる棋譜は残りません**。
- ただし、`/build-info.json`の取得は「棋譜＋AI条件」を押したとき、`/models/m6/catalog.json`の取得はモデルパネルを開いたときに発生します。そのため、**「その操作をした」という事実はアクセス記録から推測できる**可能性があります。
