| 条件 | 完了深さ・ノード | 時間・解釈 |
|---|---|---|

| 初期局面・深さ2、反復込み | 深さ2、1,697ノード（最終反復1,272） | 約331.2 ms、約5,124ノード/秒 |

合法手生成まで行う内部ノードと、合法手の存在確認だけで済む葉ではコストが違うため、ノード/秒は局面・深さ・探索設定に依存する。上記の1値を全局面・ブラウザ・M4の10万局面生成へ一律換算しない。M2のNormalはこのNative値を初期の目安にし、WASM/Workerで実測して決める。GPU推論・学習は未計測で、M6の費用には換算しない。

再現は、記録した実装コミットのソースでビルドしてから実行する。CLIはリポジトリ直下・`apps/web` のどちらからでもソースの不一致を拒否することをRED/GREENで確認した。正しい91f4c62の実行は `apps/web` から行っている。現在の実装が変わっていれば、新しい作業ディレクトリへそのコミットを展開して固定ツールチェーンでビルドする。実時間・時間上限でのノード数は負荷により変わる。

```sh
mkdir -p runs/m1
cargo build --locked --release -p voxelshogi-core --example search_bench
target/release/examples/search_bench 91f4c62c773d43559870242f21a8a1ca9b339513 > runs/m1/search-native-reproduce.json
```

`runs/m1` は事前に作成する。CLIはRuntimeのソース・Cargo設定・固定Rust・計測プログラムが指定コミットと一致しなければ失敗する。比較には同じ設定・履歴を使い、ビルド中の測定を避ける。CLI出力にないCPU/RAM・OS版・測定日のメタデータは、読み取り値と実行日を検証記録側で付記した。
