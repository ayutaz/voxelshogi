# M4-3：GPUサービスで計測し、その環境を学習へつなぐ

2026-10-28 JST。ユーザーの指定により、探索・生成・性能計測・学習・重い回帰検証はMacで実行しない。Macは編集・読み取り・軽量な静的／単体確認だけに使う。GitHub Actionsは正しさの確認、Vast.ai／CloudRiftは承認後の実機計測・生成・学習に使う。**外部実機の計測は未実施。以下は初回試行の見積もりと準備であり、本生成の確定見積もりではない。**

## 同じGPUサービスを使う順序

1. M4-3: 1台のRTX 4090ホストで、既存Rust探索とデータ生成をCPUで計測する。
2. M4-4〜5: 実効CPU速度・並列効率・検証と再生成の時間を測り、約10万局面の件数・教師条件・有効率を含む見積もりを承認後に生成する。
3. M6: 同じサービスとGPU系統を使い、CUDA版PyTorch・学習処理を実装して学習する。現在のLinux向けuv.lockはCPU版PyTorchを選んでいるため、GPUが見えることだけを学習成功とはしない。必要VRAM・学習速度・棋力・変換精度はM6で別途測る。

サービス選定を継続できるよう、ソースコミット・依存lock・実機構成・実行設定・終了手順を記録する。開発の待機時間中ずっとGPUを借り続ける計画にはせず、初回試行の記録を回収後、不要な計算資源を終了する。初回試行の承認を、本生成・本学習・データ公開の承認へ拡大しない。

| 公開構成・割当 | rentalsページでは36 vCPU・RAM80 GB・ローカル450 GBを表示 | offer `54489630`、EPYC 7K62、effective CPU24、RAM32,162 MB（API表記）、ディスク50 GB指定 |

| 未確認 | アカウントで選べる正確なSKU・地域・空き・CPU専有性・停止後の保持費。料金ページのローカル容量は420 GBで、rentalsページと差がある | 起動直前の空き・実効性能。検索結果は予約ではなく、offerは入れ替わる。停止中もディスク費が継続 |

CloudRiftを第一候補にする理由は、公開単価が近く、付属保存・転送を含む構成を比較しやすいため。vCPUの数字から速度優位を仮定せず、実際の計測で選ぶ。選択時は最低8 vCPU・RAM16 GB・空きディスク50 GB、LinuxとSSH／端末接続、RTX 4090×1とドライバを確認する。公開ページとSKUが異なる場合は、実際の構成と総額を取り直す。

**承認をお願いする初回案: CloudRiftの上記条件の1台、起動から回収・終了まで最大60分、サービス利用料の消費上限US$2。** 単価は付属ディスク等込みで$0.50/時以下を選ぶ。$0.39/時で60分なら基本利用料は$0.39。上限は準備・停止処理・予備分を含む消費枠で、$2を使い切る予定ではない。追加の有料volume・予約契約・同時2台・自動延長・自動チャージは行わない。新規入金やカード決済が必要な場合は別に案内する。

Vast.aiの表示例では、依存取得等の下り5 GBと結果回収の上り0.1 GBを仮定しても、1時間の目安は約$0.406（$0.39185＋$0.01333＋$0.00053）。この転送量は仮定であり実測ではない。CloudRiftが利用できない場合は、対象構成を提示して代替を判断する。

## 起動後に行うこと

| 経過時間の上限 | 作業と終了条件 |
|---|---|
| 0〜15分 | 正確なSKU・CPU/RAM・GPU・ドライバ・費用・接続を確認。ソースを指定コミットで取得し、Rust1.97.1、uv0.11.23、Python3.14.9と依存lockを準備 |
| 15〜35分 | Python境界の短い確認と、下記pilotを1回実行。pilot内は1ワーカー・最大240秒、所有子プロセス群RSS1 GiB、セッション合計10分。終了しなかった試行も失敗として保持 |
| 35〜45分 | report・context・完了済みのsamples・worker.logを回収し、件数・停止理由・入力hashと再生成一致を確認。Macで再探索しない。raw Parquet・入力棋譜は公開しない |
| 45〜60分 | 計算資源を終了し、残る有料volume・ディスク・予約・請求状態を確認。保持が必要なら別途見積もる |

pilotの時間制限はプロセスを止める機能で、レンタル課金の自動終了ではない。GPU起動前に、アカウント側で使える終了方法と、接続が切れた場合も制御側から終了できる経路を確認する。60分の終了責任をpilotコマンドだけへ任せない。準備や回収が時間内に収まらなければ、延長せず終了して残作業を再計画する。

## 計測コマンドと取得する証拠

新しいコマンドはLinux専用。Macでは実行を拒否する。リポジトリのcleanな指定コミットを使い、APIキーをGPUホストへ持ち込まない。Rustとuvを導入済みのGPUホストで、次を実行する。

```bash
uv --version
rustup show active-toolchain
uv sync --locked
uv run --locked python -m training.pilot runs/m4/remote-pilot --provider cloudrift --seconds 240
```

コマンド自体はインスタンスを作成・削除せず、課金APIも呼ばない。`nvidia-smi`でGPU1枚・RTX 4090・VRAM・ドライバを確認する。CPU探索の結果は、GPU学習やブラウザ推論の速度へ換算しない。

- 固定入力は既存M3の初期局面・1手後・少数駒2局面と、固定seedのランダム軌跡の64手地点。64手というだけで戦略的な中盤と断定せず、少数駒は人工的な終盤fixtureと明記する。実際の局面、履歴、hash、合法手数、盤上／持ち駒数を保存する。初期局面だけや2王だけの速さで全体を見積もらない。
- 深さ1／1,000ノードと深さ2／10,000ノードを、各局面で準備1回＋測定3回。完了深さ・停止理由・教師として使える件数を全試行で残す。未完了教師を分母から勝手に取り除かず、全試行の速度と有効教師の速度を分ける。
- 6対局×最大16手の生成・全件検証・全再生成を同じプロセス上限内で測る。保存bytes、重複、有効split件数とファイルのバイト一致を確認する。これは102行以下の小規模確認であり、10万の有効局面がそろった証拠ではない。
- context、入力hash、準備試行、各試行JSONL、全件完了時のreportを分ける。時間・メモリ等で停止した場合はcomplete=falseとし、途中のJSONL・ログを残す。再試行時は新しい出力先を使い、失敗を成功で上書きしない。
- GitHub Actionsの`--provider ci --allow-no-gpu --smoke`は小さい角の王のfixtureと9行で経路の正しさだけを確認する。CI外のno-GPU実行を拒否し、CI結果をCloudRift／Vast.aiや実GPUの性能結果にしない。

この初回試行から、次の本生成見積もりを作る。学習用に必要なrandom／rules／searchの内訳、教師の深さ／ノード、長い対局での保存サイズ、重複・未完了教師の除外後の有効率を決める。次の外部試行で並列効率と長い対局の傾向を測り、検証・再生成・転送・終了まで含めて再見積もりする。CPU数倍の線形高速化や、小標本からの確定時間は提示しない。

## 認証情報

確認時点ではリポジトリ直下と`apps/web`に`.env`／`.dev.vars`はなく、実行環境のVast.ai／CloudRift用変数も見つからなかった。これは他の端末・アカウント設定を調べた結果ではない。[.env.example](../.env.example)は空の変数名だけを用意している。

ローカル制御用に`.env.example`を`.env`へコピーし、`CLOUDRIFT_API_KEY`（必要なら`VAST_API_KEY`）をローカルのエディタで入力する。`.env`はgitignore対象。キーを会話・ログ・PRへ貼らず、GPUホストへコピーしない。pilotは`.env`を読み込まず、キーが設定されただけで契約・起動を始めない。実行前に認証付きで構成・残高・費用・終了方法を読み取り確認する。
