## 目的と固定条件

教師模倣精度と棋力を分けて測り、手数打切りに隠れる問題を診断する。
露出済みの8開始局面を使う開発用試行で、未知の強さの最終holdoutではない。
詰みを含む戦術4件は同じ系統の変形で、独立した4戦術とは扱わない。

| 項目 | 固定値 |
|---|---|
| 実行元 | `bbc518dfa8f735aabeb55de289027b8ccccfce58`、clean source |
| 対照 | M1対M1、8組・先後交換16局 |
| モデル比較 | 凍結したM6-SのTorch CUDA合法argmax対M1、同じ8組16局 |
| 探索 | 深さ3、20,000ノード、TT4,096。着手選択の時間上限は使わない |

両方が事前screenを満たした。M1同士の完了局だけの勝点率は50%。
M6の開始全局を分母とした勝率は12.5%、観測した8組のpaired bootstrapは
0〜31.25%。少数・関連局面の再標本化なので、母集団の勝率保証やEloへ使わない。
評価v1とは局面・探索・手数上限が異なり、勝ち数の増加を学習による改善としない。

戦術4局面でM6が手番を持つ4局は、2勝・2打切りだった。
元の2局面では`232341`／`878769`を選び、1手の上限内に勝たなかった。
自王位置を変えた2局面では`899999`／`211111`で勝ちが確定した。
事前oracleの手だけが勝ち手とは限らず、Rustで再生した実結果で数える。
M1が手番を持つ対応4局はいずれも1手で勝った。

標準序盤開始のM6は1敗・1引分、追加103／490手で終局。
96手履歴からのM6は1敗・1打切り、追加343／512手だった。
短い戦術と長期対局の両方で差を観察できたが、棋力改善は確認できていない。

## 再生・漏洩監査の範囲

保存前と保存後に全32棋譜をRustで再生し、宣言結果・手数・全ファイルhash・
再集計を照合した。入力116,921行（重複行・全splitを含む）に対し、
評価開始後の全継続局面と終端を調べた。対照371、M6比較1,347の一意な物理局面で、
train／val／testとの重なりは全て0だった。共通bookの開始前履歴は対象外。

IDはruleset・盤・持ち駒・手番を含み、plyを除く。
これは凍結M6コーパスに対する物理局面の監査であり、
後続データや手番正規化後の特徴量同値まで監査した結果ではない。
次のデータでは、モデル入力の同値性と履歴も分けて確認する。

公開するJSONは集計・hash一覧・照合receiptで、重み・Parquet・全棋譜本体は含めない。
元の小さい実行記録は制御側へ退避した。大きい入力はMacへ中継していない。

## 時間・費用・資源終了

worker全体は約100.6分。対局内の合計は対照約16.4分、M6約23.4分で、
残りは入力取得・照合・準備・再生・監査などを含む。
同じVMの別checkoutで小さい境界テストも実行したため、専有性能の比較には使わない。
worker RSS観測最大約1.61GiB、GPUメモリ観測最大739MiBはdevice全体の値で、
単一モデルへ帰属させない。

取得時の単価はUS$0.65/時、上限4時間／US$4を予約した。
全体の保守的予約上限はUS$65／基本枠100、追加US$100は未使用。
実請求は未回収で、予約上限を支出額や残高と呼ばない。
05:09 UTCに終了要求し、05:13 UTCに`Inactive`・`resources_released=true`を確認した。
独立した終了guardは起動前にPID・tag・期限hashで照合したが、
今回は期限前に終了したため、実期限到達による自動停止は未実測。
