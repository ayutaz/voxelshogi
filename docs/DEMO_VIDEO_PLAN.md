## 目的とゴール

Xのタイムラインを眺める人に、最初の3秒で「将棋が9層の立体になり、駒が層をまたぐ」意外性を伝える。
続く映像でAI同士を眺めるサービスだと理解でき、公開URLから観戦を始めたくなる構成にする。
完成物は**15秒のMP4本編1本、冒頭3秒の候補2本、ポスター画像1枚、字幕・素材と再制作手順**。
バズを狙う制作方針であり、拡散数を保証するものではない。公開後の反応と制作の合否は分ける。

## 最初の3秒

ロゴだけの画面、タイトルアニメーション、ロード待ち、設定画面から始めない。最初のフレームから実際の盤と駒を見せる。

| 時間 | 映像 | 字幕・狙い |
|---|---|---|
| 0.0〜0.7秒 | 9層だと分かる斜めの立体盤。これから動く駒と移動先の層に視線を集める | **「将棋、9層にした。」**。最初のフレームから表示し、文字を読む時間を確保 |
| 0.7〜2.2秒 | 実際に合法な層をまたぐ一手。移動元・先と軌跡を強調し、字幕を維持 | 言葉だけでなく動きで三次元の違いを見せる |
| 2.2〜3.0秒 | 同じ局面の着地を見せ、盤全体との位置関係を残す | 異層の駒取りがある実棋譜ならその着手を優先。取れない局面へ偽の駒取りを加えない |

**候補A**は上記の全体像＋「将棋、9層にした。」。
**候補B**は動く駒を大きく見せ、少し引いて別の層への着地を示す＋「その一手、別の階へ。」。
新UI版は0秒で全体を見せ、0.4〜0.8秒に中央の実異層着手へ寄る。修正版では候補A 1.10倍、候補B 1.12倍に抑え、盤全体が字幕帯の外へ収まることを検査する。旧1.7／1.95倍は見切れを生じたため採用しない。アプリの未実装のカメラ機能として紹介しない。
同じ棋譜・着手・尺で比較する。Aを既定とし、9層の認識、駒の動きの判別、文字の可読性を理由付きで比較して選ぶ。
候補を用意したことを視聴者によるA/Bテスト済みとは呼ばない。

## 15秒本編の構成

| 時間 | 画面・操作 | 伝える内容 |
|---|---|---|
| 0〜3秒 | 上記のフック | 立体将棋の意外性 |
| 3〜7秒 | 同じ対局の実際の着手を続け、移動元・先・層を追う | 「AI同士の対局を、眺める。」。実際に使ったAI条件を小さく併記 |
| 7〜11秒 | 一時停止→明示分岐して新しい1手を指す実操作を等倍で見せる | 「止めて、一手ずつ追える。」。2D盤・主要ボタン・速度スライダーを切らず、履歴送りと新しいAI着手を混同しない |
| 11〜15秒 | 盤を残し、公開URLと短い案内を重ねる | 「ブラウザで観戦」＋`voxelshogi.yousan-apps.workers.dev`。4秒間読める状態にする |

無音でも成立させ、ナレーションを必須にしない。音を付ける場合も字幕を残し、利用許諾の確認できる素材だけを使う。
説明用の字幕や拡大は編集で加えられるが、操作できない機能を実装済みのUIに見せない。
着手を短縮・倍速にする場合は「再生速度変更」等を表示し、実際のAI応答時間と区別する。

## 素材と制作手順

1. **素材を固定**：既存の標準1王ルールの公開可能な棋譜から、合法な異層着手のある箇所を選ぶ。9王実験や非公開の他者棋譜を使わない。
2. **合法性を確認**：Rustで全手再生し、選んだ手・局面・結果を照合する。棋譜SHA、ruleset、AI条件、app commit、収録対象buildを記録する。未確認の詰み・勝敗を演出しない。
3. **候補2本を作る**：字幕と画角を比較し、最初の3秒を先に確定する。絵コンテ・字幕の準備はUI実装と並行して進める。
4. **実画面を収録**：L1〜L3の完成版で、同じ棋譜を再生する。収録・エンコードはGitHub Actions等のLinuxで実行し、Macでは編集・軽量な目視確認にとどめる。新たなGPU契約・学習を先行条件にしない。
5. **本編を編集・検査**：字幕、動き、URLを結合し、下記の完成判定を行う。L6で実際の公開版と照合し、相違があれば該当箇所を再収録する。
6. **納品**：本編、候補2本、ポスター、字幕・shot list・制作コマンド・hashをそろえる。大きな収録元動画をgitへ入れず、CIの期限付き成果物から確認できるようにし、最終公開用MP4を確定する。認証情報・ユーザー棋譜・ブラウザprofileを成果物へ含めない。

通常はモデル不要のEasy／Normalで撮れる構成にする。Sを使う場合は取得・許諾の条件を満たし、使用したモデルと精度形式を記録する。
Mを配布済み・強いAIを実証済みとは説明しない。L4未完了ならCloudflareへの保存を映像で約束しない。

## 書き出し仕様

- 本編：**15秒、1080×1350（4:5）、30fps、MP4／H.264／yuv420p**を制作目標とする。音を入れる場合はAAC。
- 冒頭候補：同じ形式で各3秒、2本。ポスター：本編から内容を代表する1フレームを画像化。共有用OGPは同じ実盤面から1200×630で作り、説明を盤の外へ置く。
- スマホ幅390px相当で字幕・動く駒・URLを目視確認し、端や操作用overlayで隠れる場合は配置を直す。
- 30fpsは映像の書き出し設定であり、アプリの実機FPSの計測結果ではない。

X公式の[動画制作の案内](https://business.x.com/en/advertising/creative-best-practices)が勧める、冒頭の動きと無音向け字幕を参考にする。
[Media Studioの形式案内](https://help.x.com/en/using-x/media-studio-faqs)でH.264・AAC・MP4を確認した（2026-11-13 JST）。
広告向けの制作指針を通常投稿の拡散保証とは扱わない。上記の15秒・4:5は本企画の編集方針であり、Xの最大制限ではない。投稿前に利用するアカウントと投稿経路でアップロード可否を確認する。

## 実制作の実行と納品確認

`Demo video`は手動起動、または同じrepoのPRへ`record-demo`ラベルを付けた時だけ起動し、PRの作成・pushごとには録画しない。
ラベル起動は取り込み前の候補確認用で、記録の`candidate=true`を保持する。最終納品はmainでの手動起動から生成し直す。
LinuxでWASMと同じcommitのアプリをbuildし、実際のEasy Worker同士を32手まで進める。
その中の異層着手を冒頭へ選び、同じ棋譜を履歴で再生する。7〜11秒は履歴移動で一時停止した実画面で1手送りを操作し、停止中の表示を保持する。短い場面に開始／停止／追加送りを詰め込まず、最終的に表示した棋譜を保存する。
これは動画素材のための小さい対局で、停止中の研究データ生成・モデル学習やGPU契約を再開するものではない。

録画の準備部分は緑一色のmarkerで区切り、実動画の画素から最初の本編frameを求めて切り落とす。
15秒本編・3秒候補2本を実ファイルへ書き出し、`ffprobe`でcodec・解像度・450／90 frame・尺を検査する。
長い停止後の最初の描画時間をアニメーションの経過時間へ足してしまう問題も、失敗テストを先に追加して修正した。新しい着手の軌跡は移動元から始まり、一度到着すると描画要求を止める。
字幕は無音向けに焼き込み、使用AIをEasyと明記する。書き出し30fpsをアプリの実機性能とは呼ばない。

生成後は7日間の`demo-video-<SHA>`成果物から、本編・候補2本・ポスター・0／0.7／1.5／2.9／7.5／11.5秒の確認画像・実棋譜・字幕・hash記録を確認する。
未編集の長い録画、モデル、ブラウザprofile、認証情報は成果物へ含めない。
Macでは最終動画・小さい確認画像と記録だけを読み、連続録画・エンコードは実行しない。

```bash
# アプリを公開し、main HEADと公開buildのSHAが一致する段階で一度実行する
# 完了文書だけのPRをmergeした後はmain HEADが進むため、同じ版とは限らない
gh workflow run demo-video.yml --ref main -f verify_ui=false -f verify_public_storage=true
```

CIの取得は最短10分間隔。生成が成功しても完成判定の目視確認・OGPへの反映・公開版との一致が残る。
