# VoxelShogi ルール仕様 (`ruleset_id = voxelshogi-standard-v1`)

## 1. 盤と座標

- 盤は 9×9×9 の 729 マス。
- 内部座標は 0-indexed の `(x, y, z)`。各値は 0..8 で、マス番号は `z*81 + y*9 + x`。

| 内部 | 意味 | 表示 |
|---|---|---|
| `x` | 筋 | `x+1`（1..9）。先手から見て右端が1筋（通常の将棋と同じ） |
| `y` | 段 | `y+1` を漢数字（一..九）で表す。一段目 (`y=0`) は後手の最奥 |
| `z` | 層 | `z+1` をローマ数字（I..IX）で表す。両者共通の上下方向 |

- 先手（☗, Black）の前方は **y の減少方向**、後手（☖, White）の前方は **y の増加方向**。z 方向に前後の区別はない。
- 表示例: `(4,4,4)` は `5五V`。ASCII表記は3桁の数字 `筋段層` で、`555` となる。

## 2. 初期配置（各186枚・計372枚）

先手の配置を示す。後手の配置は、盤の中心に対する点対称 `(x,y,z) → (8-x, 8-y, 8-z)` である。

- **七段目 (`y=6`)**: 全81マスに歩。
- **八段目 (`y=7`)**: 中心から1マス空けた 7×7 の外周リング（`max(|x-4|,|z-4|) = 3`、24マス）。
  - 飛車12枚: 2筋 (`x=1`) の層 II..VIII と、層 II (`z=1`) の 3..7筋。
  - 角12枚: 8筋 (`x=7`) の層 II..VIII と、層 VIII (`z=7`) の 3..7筋。
- **九段目 (`y=8`)**: 玉 `(4,8,4)` を中心とする同心の正方形。`d = max(|x-4|,|z-4|)` によって駒が決まる。
  - d=0: 玉（1枚）、d=1: 金（8枚）、d=2: 銀（16枚）、d=3: 桂（24枚）、d=4: 香（32枚）。

## 3. 駒の動き

先手を基準に `(dx, dy, dz)` で記述する（前方は `dy = -1`）。後手は `dy` の符号を反転する。

| 駒 | 動き | マス数（中央・空盤） |
|---|---|---|
| 歩 | 同じ層で前方へ1マス `(0,-1,0)` | 1 |
| 香 | 同じ層で前方へ、駒にぶつかるまで | 最大8 |
| 桂 | `(±1, -2, ±1)` の4マスに跳ぶ（x と z を**両方**±1する）。間の駒は飛び越せる | 4 |
| 銀 | 前方の 3×3（`dy=-1` の全9マス）＋ 上下層の斜め後方 `(±1, +1, ±1)` の4マス。**同じ層の斜め後ろには動けない** | 13 |
| 金・と・成香・成桂・成銀 | 周囲26マスから、同じ層の斜め後方 `(±1,+1,0)` の2マスと、上下層の後方の列 `(*,+1,±1)` の6マスを除いた18マス | 18 |
| 玉 | 周囲26マス | 26 |
| 飛 | x・y・z の**いずれか1つ以上**が移動元と同じマスへ移動できる | 216 |
| 竜 | 飛の動き ＋ 周囲26マス | 224 |
| 角 | 2軸を同じ距離 `a` 動かし、残り1軸を `a` 以下だけ動かす（静止も可） | 224 |
| 馬 | 角の動き ＋ 周囲26マス | 230 |

### 3.1 飛車の遮り

始点と終点を対角とする軸平行の直方体（実際には長方形または線分）の中に、両端以外の駒が1枚でもあれば移動できない。たとえば `(1,-1,0)` への移動は、`(1,0,0)` と `(0,-1,0)` のどちらに駒があっても遮られる。

### 3.2 角の遮り（10/17 改定後）

終点を `(a, a, b)`（2軸の移動量の絶対値が `a`、残り1軸 c の移動量の絶対値が `b ≤ a`）とする。等しい2軸がなす平面の対角方向に `m` 歩（1 ≤ m ≤ a）進んだ各地点で、c 軸方向に終点の向きへ `0..min(m, b)` だけ立ち上がった領域が、遮り判定の対象になる。この領域が「台形」である。台形のうち終点を除くマスに駒があれば、移動できない。

- `b = 0` の場合は、平面上の普通の斜めの直線になる。
- `b = a`（3軸すべての移動量が等しい空間対角）の場合は、3通りの軸の組それぞれの台形が**すべて**空いている必要がある。
- 台形は始点側から定義されるため、**遮りは非対称**である。例: `(0,0,0)→(2,2,1)` は `(1,1,0),(1,1,1),(2,2,0)` に遮られるが、逆向きの `(2,2,1)→(0,0,0)` は `(1,1,1),(1,1,0),(0,0,1)` に遮られる。

### 3.3 竜・馬の追加の動き

竜と馬が持つ周囲26マスへの1歩の動きは、遮られない。そのため、たとえば竜の `(1,-1,0)` は、飛車の遮りの判定とは無関係に常に移動できる。

## 4. 成り

- 敵陣は相手側の3段（先手は `y ∈ {0,1,2}`、後手は `y ∈ {6,7,8}`）。層の位置は問わない。
- 移動元または移動先が敵陣にあるとき、成ることができる（任意）。
- 成れる駒は歩・香・桂・銀・角・飛。金と玉は成れない。
- **行き所のない駒の禁止**: 移動先から盤上で動ける地点が1つもなくなる場合は、成りが必須になる（先手の歩・香は一段目 `y=0`、先手の桂は一・二段目 `y≤1`）。打つ場合も同じ場所には打てない。
  - 根拠: 将棋ったーは、空盤での利きが盤内に1つでもあるかどうかで判定している。銀は一段目でも後方への動きが残るため、成りは必須にならない。

## 5. 持ち駒と駒打ち

- 取った駒は成っていない状態に戻し、持ち駒にする。
- 空いているマスに打てる。打った手で成ることはできない。
- **二歩**: 同じ**層と筋**（同じ `(x, z)` の列）に、自分の成っていない歩がすでにある場合は、歩を打てない。
- **打ち歩詰め**: 歩を打って相手玉を詰ませる手は禁止。
  - 根拠: 標準将棋の既定を継承。将棋ったーの詰み判定にも打ち歩詰めの例外処理がある。

## 6. 勝敗と終局

| 条件 | 結果 |
|---|---|
| 手番側に合法手がない（詰み） | 手番側の負け |
| 投了 | 投了側の負け |
| 同一局面（盤面・両者の持ち駒・手番）が4回出現（千日手） | 引き分け |
| 千日手の間、一方の指し手がすべて王手（連続王手の千日手） | 王手をかけ続けた側の反則負け |

- 自玉を王手された状態のまま放置する手（王手放置）や、自殺手は、**合法手に含めない**。そのため、反則負けとして処理することはない。
- 入玉宣言、持将棋、トライルールは**ない**（将棋ったーの既定に従う）。
- 実装上の判断: 王手されていないのに合法手がない状態（ステイルメイト）も「合法手がない」として、手番側の負けとする。持ち駒がある限り事実上起こらない。
- ルール外の打ち切り: AI対局やデータ生成では、ルールとは別枠の設定として「最大手数による引き分け打ち切り」を使ってよい。その場合、棋譜には打ち切りであることを記録する（`GameRecord` の終局理由 `MaxPlies`）。この設定は `ruleset_id` に含めない。

## 7. 表記

- マス: `筋段層` の3桁の数字。例: `577`（5筋七段 VII層）。
- 指し手（盤上の移動）: `移動元移動先` の6桁に、成る場合は `+` を付ける。例: `577567`、`523513+`。
- 指し手（駒打ち）: `駒の文字*マス`。例: `P*565`、`G*111`。駒の文字は `P L N S G B R`。
- 局面の文字列表記（VSFEN）の詳細は `docs/GAME_ENGINE.md` に記載する。

## 10. 比較実験用の9王ルール（v0）

2026-10-26、ユーザー指示によるAI対AI比較・観戦表示の試作に使用する。公開版の標準ルールを置き換える採用決定ではない。

| ruleset_id | 勝利条件 |
|---|---|
| `voxelshogi-nine-kings-first5-v0` | 相手の王を5枚取った着手の直後に勝ち |
| `voxelshogi-nine-kings-all-v0` | 相手の王を9枚すべて取った着手の直後に勝ち |
| `voxelshogi-nine-kings-score-v0` | 指定した偶数の上限plyで、捕獲した王が多い側が勝ち。同数は引き分け |

- 通常将棋と同じ中央V層の初期配置を全9層に置く。各180枚・王9枚、合計360枚。2陣営が交互に1手指す。
- 駒の立体移動・遮り・成り・二歩・行き所のない駒は§3〜5と同じ。王手回避・詰み・打ち歩詰め・連続王手による敗北は使わない。
- 王を取ると捕獲した側の得点を1増やして盤から取り除く。王は持ち駒にせず、再投入・成り・復活を認めない。他の駒は従来どおり持ち駒にして打てる。
- 同一の盤面・持ち駒・手番が4回出現した場合、および合法手がない場合は引き分け。規定手数の得点比較以外では、実験上限での打ち切りも引き分けとする。
- 5先取／全王捕獲の自然な勝利が上限の着手と同時に成立した場合は勝利を優先する。得点比較ルールでは全王捕獲だけでは終了しない。
- 実装で受け付ける上限は2〜2,000の偶数plyとし、ルールIDとは別に棋譜へ保存する。規定手数比較の上限と、他候補の実験上の打ち切りを区別して記録する。
- 棋譜・AI設定・seed・結果・最終局面ハッシュを保存し、標準ルールの棋譜と混ぜない。先行調査は [比較調査](RULE_VARIANTS_RESEARCH.md)、実施済みの対局・公開表示・再現手順は [R0実測報告](NINE_KINGS_EXPERIMENT.md) に記録する。

### 実験棋譜とAI設定

実験棋譜のschemaは `voxelshogi-capture-experiment-v1`。固定初期配置からの全着手、`ruleset_id`、偶数の `max_plies`、seed（対戦組）、`swapped`（seedストリームの先後交換）、探索の深さ・幅、実装版 `engine`、結果、最終Zobristハッシュを保存する。結果やハッシュは全手をRustで検証・再生して照合する。表示側では配信ファイルのSHA-256も照合する。

試作用AIは手の候補を幅で制限したnegamax探索であり、学習モデルでもM1完成版でもない。王捕獲・駒得・前進の評価、捕獲／成り優先の候補順、seedでの同順位解決を全候補で共通にする。時間制限で着手を変えず、深さ・幅・seed・実装版で再現する。
