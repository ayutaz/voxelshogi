## AI 研究からの採用方針（案）

- 探索は Gumbel AlphaZero 系を使う（少ないシミュレーション数でも方策改善が保証される）。KataGo の playout cap randomization も取り入れる。
- Value は W/D/L の3値ヘッドにする。報酬は勝敗のみとし、手作りの報酬調整はしない。観測は手番側の視点で作る。
- Policy は、Chessformer / lc0 型の from-to アテンションヘッドにする（729×729 のロジットに、成りのバイアスと打ちのロジットを加える）。将棋ったーの飛角は移動先の領域が広く、方向ベースの行動空間では表現が爆発するため。
- Geometry-aware バイアスを729トークンにそのまま適用すると、約1.36億パラメータの共有射影が必要になる。そのため、軸ごとに分解するか、静的な3D相対バイアス（ヘッドごとに4,913エントリ）を使う。
- 評価は、同じ FLOPs のもとでの Elo で行う。幾何を考慮すると精度は上がっても勝率は上がらない、という先行報告があるため。

## 技術上の主要リスク

1. ONNX Runtime Web の WebGPU 用 wasm が、Cloudflare Static Assets の1ファイル25MiB上限を超える（27MiB）。R2 で配信するか、軽量ビルド（JSPI 16MiB、WASM のみ 13.6MiB）を使う。
2. WebGPU では、Conv3d が最適化されていない汎用カーネルでしか動かない。ONNX 標準の `Attention` 演算子は CPU で実行される。→ 本格学習の前に、小型モデルで実測する。
3. RTX 5090 では、CUDA 13 版の PyTorch が必要。
4. ローカルのディスク空きが約7GB しかない。
